## 递推：已知小问题，求出大问题

先考虑一个自编问题：有 n 级台阶，每次走 1 级或 2 级，走到第 n 级有多少种不同走法？约定 `0 <= n <= 40`。

例如 n=3，走法有：

```text
1 + 1 + 1
1 + 2
2 + 1
```

答案是 3。n 更大时，直接列出所有走法会越来越麻烦。我们换个方向：**先看最后一步从哪里来。**

走到第 i 级，最后一步只有两种情况：

1. 从第 i−1 级走 1 级过来。
2. 从第 i−2 级走 2 级过来。

这两类不会重复，而且包括所有走法。用 f[i] 表示“走到第 i 级的走法数”，就得到：

```text
f[i] = f[i - 1] + f[i - 2]
```

这样的等式叫**递推关系**：用较小问题的答案，计算当前问题的答案。

### 初始值为什么这样设

- f[0]=1：还在原地时，有一种“什么都不走”的方式。它也让“从第 0 级直接走到第 2 级”这条路线得到正确计数。
- f[1]=1：只能走一次 1 级。

再从 i=2 开始计算：

| i | 计算过程 | f[i] |
| --- | --- | --- |
| 0 | 初始值 | 1 |
| 1 | 初始值 | 1 |
| 2 | f[1]+f[0] | 2 |
| 3 | f[2]+f[1] | 3 |
| 4 | f[3]+f[2] | 5 |
| 5 | f[4]+f[3] | 8 |

### 把关系写成循环

```cpp
#include<bits/stdc++.h>
using namespace std;

long long f[45];

int main() {
    int n;
    cin >> n;
    f[0] = 1;
    f[1] = 1;
    for (int i = 2; i <= n; i++) {
        f[i] = f[i - 1] + f[i - 2];
    }
    cout << f[n] << '\n';
    return 0;
}
```

输入 `5`，输出 `8`。数组把已经算好的结果保存下来；计算 f[i] 时，前面的两个值已经可用，所以循环从小到大执行。

这个程序的时间复杂度是 O(n)，数组空间是 O(n)。注意我们约定了 n≤40；**数值范围由题目决定，数组开够后还要检查答案能否装进所选类型。**

## 例题精讲：P1028 · 数的计算

**原题：** [P1028 · 数的计算](https://www.luogu.com.cn/problem/P1028)。

**题意简述：** 从只包含正整数 n 的数列开始，可以在末尾添加一个正整数，但新数不能超过当前末项的一半；可以在任何一步停止。求一共有多少个不同的合法数列。`1 <= n <= 1000`。

### 先把 n=6 的情况列全

```text
[6]
[6, 1]
[6, 2]
[6, 3]
[6, 2, 1]
[6, 3, 1]
```

一共 6 个。这里的方括号只是帮助我们看清数列中的各项，不是题目要求的输出格式。

输入：

```text
6
```

输出：

```text
6
```

### 只考虑“下一个数选多少”

用 f[x] 表示“以 x 开头的合法数列个数”。

第一种情况是什么都不加，只有 [x]，贡献 1。

如果继续添加，下一个数可以选 1、2、……、x/2。C++ 中正整数的 x/2 会向下取整，例如 7/2=3。

- 选 1 后，后面的全部变化共有 f[1] 种。
- 选 2 后，后面的全部变化共有 f[2] 种。
- 依次类推，选到 x/2。

所以：

```text
f[x] = 1 + f[1] + f[2] + ... + f[x / 2]
```

为什么可以把它们相加？不同选择的第二项不同，得到的数列就不同，各类之间不会重复；所有合法的第二项也都列到了。

x=1 时，不能再加正整数，所以 f[1]=1。也可以统一令每个 f[x] 先等于 1，再把后面各项加上；x=1 时内层循环自然不执行。

| x | 计算 | f[x] |
| --- | --- | --- |
| 1 | 只有自身 | 1 |
| 2 | 1+f[1] | 2 |
| 3 | 1+f[1] | 2 |
| 4 | 1+f[1]+f[2] | 4 |
| 5 | 1+f[1]+f[2] | 4 |
| 6 | 1+f[1]+f[2]+f[3] | 6 |

### 完整代码：从小到大递推

```cpp
#include<bits/stdc++.h>
using namespace std;

long long f[1005];

int main() {
    int n;
    cin >> n;

    for (int x = 1; x <= n; x++) {
        f[x] = 1;
        for (int next = 1; next <= x / 2; next++) {
            f[x] += f[next];
        }
    }

    cout << f[n] << '\n';
    return 0;
}
```

外层计算 f[x] 时，next 最大只有 x/2，比 x 小，因此 f[next] 已经算好。

两层循环总计不超过 n² 次，时间 O(n²)；n≤1000，代入后最多一百万这个量级，可以通过。数组空间 O(n)，用 long long 保存计数。


## 递推的常用应用：前缀和

假设一组数是 2、4、1、5、3，我们要反复回答“第 l 个到第 r 个数加起来是多少”。

每次都从 l 加到 r，一次查询最多看 n 个数；m 次查询就是 O(nm)。如果 n、m 都是十万，计算量可以达到 10¹⁰。

注意到：从第 1 个开始的累计和，可以沿着数组一路算出来。用 s[i] 表示**前 i 个数的和**，就有：

```text
s[0] = 0
s[i] = s[i - 1] + a[i]
```

s 就叫**前缀和数组**。它也是递推：已经知道前 i−1 个数的和，再加上当前数，就得到前 i 个数的和。

| i | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| a[i] | 没有元素 | 2 | 4 | 1 | 5 | 3 |
| s[i] | 0 | 2 | 6 | 7 | 12 | 15 |

### 为什么区间和是 s[r]−s[l−1]

以第 2 个到第 4 个数为例：

```text
s[4] = a[1] + a[2] + a[3] + a[4]
s[1] = a[1]

s[4] - s[1] = a[2] + a[3] + a[4] = 10
```

推广后，**包含两端的 [l,r] 区间和**就是：

```text
sum(l, r) = s[r] - s[l - 1]
```

先计算前 r 个数的和，再去掉前 l−1 个数，恰好留下 l 到 r。

> **前缀和的边界从 s[0]=0 开始。**
>
> 数据存放在 a[1] 到 a[n]，前缀和开到 s[n]，数组至少需要 n+1 个位置。查询 l=1 时，使用 s[r]−s[0]，不需要另写一种计算规则。
>
> 这里减去的是 s[l−1]，不是 s[l]；否则会把第 l 个数也一起减掉。累计和的范围也要单独检查，不能只看一个 a[i] 有多大。

### 配套例题：P8218 · 求区间和

**原题：** [P8218 · 求区间和](https://www.luogu.com.cn/problem/P8218)，来自[优先参考题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 输入 n 个正整数，再输入 m 个区间 [l,r]，逐行输出每个区间内所有数的和。n、m≤10⁵，a[i]≤10⁴。

输入：

```text
5
2 4 1 5 3
3
2 4
1 5
3 3
```

输出：

```text
10
15
1
```

第一问是 4+1+5；第二问包含整个数组；第三问只有一个元素。

```cpp
#include<bits/stdc++.h>
using namespace std;

long long s[100005];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    s[0] = 0;
    for (int i = 1; i <= n; i++) {
        int value;
        cin >> value;
        s[i] = s[i - 1] + value;
    }

    int m;
    cin >> m;
    for (int i = 0; i < m; i++) {
        int l, r;
        cin >> l >> r;
        cout << s[r] - s[l - 1] << '\n';
    }
    return 0;
}
```

读入时就可以计算 s[i]，因此这里不用另外保存 a 数组。构建前缀和用 O(n)，每次查询只做一次减法，是 O(1)；总时间 **O(n+m)**，空间 O(n)。

**先把会反复使用的信息算好，后面的查询就能直接取用。** 这是我们在枚举优化中见过的预处理思路，现在有了一个很常用的具体工具。
