## 递推：已知小问题，求出大问题

先考虑一个自编问题：有 n 级台阶，每次走 1 级或 2 级，走到第 n 级有多少种不同走法？约定 `0 <= n <= 40`。

例如 n=3，走法有：

```text
1 + 1 + 1
1 + 2
2 + 1
```

答案是 3。n 更大时，直接列出所有走法会越来越麻烦。我们换个方向：**先看最后一步从哪里来。**

走到第 i 级，最后一步只有两种情况：

1. 从第 i−1 级走 1 级过来。
2. 从第 i−2 级走 2 级过来。

这两类不会重复，而且包括所有走法。用 f[i] 表示“走到第 i 级的走法数”，就得到：

```text
f[i] = f[i - 1] + f[i - 2]
```

这样的等式叫**递推关系**：用较小问题的答案，计算当前问题的答案。

### 初始值为什么这样设

- f[0]=1：还在原地时，有一种“什么都不走”的方式。它也让“从第 0 级直接走到第 2 级”这条路线得到正确计数。
- f[1]=1：只能走一次 1 级。

再从 i=2 开始计算：

| i | 计算过程 | f[i] |
| --- | --- | --- |
| 0 | 初始值 | 1 |
| 1 | 初始值 | 1 |
| 2 | f[1]+f[0] | 2 |
| 3 | f[2]+f[1] | 3 |
| 4 | f[3]+f[2] | 5 |
| 5 | f[4]+f[3] | 8 |

### 把关系写成循环

```cpp
#include<bits/stdc++.h>
using namespace std;

long long f[45];

int main() {
    int n;
    cin >> n;
    f[0] = 1;
    f[1] = 1;
    for (int i = 2; i <= n; i++) {
        f[i] = f[i - 1] + f[i - 2];
    }
    cout << f[n] << '\n';
    return 0;
}
```

输入 `5`，输出 `8`。数组把已经算好的结果保存下来；计算 f[i] 时，前面的两个值已经可用，所以循环从小到大执行。

这个程序的时间复杂度是 O(n)，数组空间是 O(n)。注意我们约定了 n≤40；**数值范围由题目决定，数组开够后还要检查答案能否装进所选类型。**

> **写递推，先回答三个问题。**
>
> f[i] 具体表示什么？它由哪些更小的答案得到？最开始哪些值可以直接确定？
>
> 关系写对之后，还要让计算顺序保证“用到的值已经算好”。

## 递归：把较小的问题交给同一个函数

第一章学过函数。一个函数如果在执行过程中调用自己，就叫**递归**。

以阶乘为例：

```text
4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1 × 0!
0! = 1
```

计算 n! 时，只要知道 (n−1)!，再乘 n 就行；n=0 时直接返回 1，不再调用。这正好可以写成函数。

下面也是本地演示，输入范围为 `0 <= n <= 20`。20! 为 2432902008176640000，能放入 long long；21! 已超过有符号 64 位 long long 的范围。

```cpp
#include<bits/stdc++.h>
using namespace std;

long long factorial(int n) {
    if (n == 0) {
        return 1;
    }
    long long smaller = factorial(n - 1);
    return n * smaller;
}

int main() {
    int n;
    cin >> n;
    cout << factorial(n) << '\n';
    return 0;
}
```

输入 `4`，输出 `24`。

### 调用之后，原来的函数在等什么

不要把递归想成程序突然重新开始。每次函数调用都有自己的参数和局部变量。

算 factorial(3) 时，调用过程可以这样画：

```text
进入 factorial(3)，n=3，等待 factorial(2)
    进入 factorial(2)，n=2，等待 factorial(1)
        进入 factorial(1)，n=1，等待 factorial(0)
            进入 factorial(0)，直接返回 1
        factorial(1) 得到 smaller=1，返回 1×1=1
    factorial(2) 得到 smaller=1，返回 2×1=2
factorial(3) 得到 smaller=2，返回 3×2=6
```

**调用时向更小的问题走，返回时把结果逐层交回来。** 外层函数没有消失，而是暂停在调用处，等结果回来后继续执行下一行。

### 出口与规模缩小

递归必须有两件事：

- **出口：** 哪些情况可以直接给出结果？阶乘的出口是 n=0。
- **向出口靠近：** 每次调用怎样让问题变小？这里是 n 变成 n−1。

如果漏写出口，或者一直调用 factorial(n)，函数就会不断调用下去。每一层调用还要占用保存现场的空间，这叫**调用栈**；层数过深会耗尽栈空间，出现 RE。

阶乘递归一共约 n 层，时间 O(n)，调用栈空间 O(n)。循环写阶乘只需要几个变量，额外空间可以是 O(1)。

## 递推与递归：同一关系，两种计算方向

| 方法 | 从哪里开始 | 怎样推进 |
| --- | --- | --- |
| 递推 | 已知的初始值 | 按顺序算出更大的答案 |
| 递归 | 想求的目标 | 调用较小问题，等它返回后组合 |

同一个关系，常常既能写循环递推，也能写递归。但**递归不是“把循环换成函数”就一定更快**，还要看调用总次数。

比如直接写 `ways(n - 1) + ways(n - 2)` 求走台阶：

```text
ways(5)
├─ ways(4)
│  ├─ ways(3)
│  └─ ways(2)
└─ ways(3)  ← 又计算了一次
   ├─ ways(2)
   └─ ways(1)
```

相同的 ways(3)、ways(2) 会反复展开。直接递归的调用量按指数增长，可以用 O(2ⁿ) 作上界；前面的递推只把每个 f[i] 算一次，是 O(n)。

这引出一个很实用的办法：**把算过的答案记下来，下次直接取。** 后面会用数组实现它。

## 例题精讲：P1028 · 数的计算

**原题：** [P1028 · 数的计算](https://www.luogu.com.cn/problem/P1028)。

**题意简述：** 从只包含正整数 n 的数列开始，可以在末尾添加一个正整数，但新数不能超过当前末项的一半；可以在任何一步停止。求一共有多少个不同的合法数列。`1 <= n <= 1000`。

### 先把 n=6 的情况列全

```text
[6]
[6, 1]
[6, 2]
[6, 3]
[6, 2, 1]
[6, 3, 1]
```

一共 6 个。这里的方括号只是帮助我们看清数列中的各项，不是题目要求的输出格式。

输入：

```text
6
```

输出：

```text
6
```

### 只考虑“下一个数选多少”

用 f[x] 表示“以 x 开头的合法数列个数”。

第一种情况是什么都不加，只有 [x]，贡献 1。

如果继续添加，下一个数可以选 1、2、……、x/2。C++ 中正整数的 x/2 会向下取整，例如 7/2=3。

- 选 1 后，后面的全部变化共有 f[1] 种。
- 选 2 后，后面的全部变化共有 f[2] 种。
- 依次类推，选到 x/2。

所以：

```text
f[x] = 1 + f[1] + f[2] + ... + f[x / 2]
```

为什么可以把它们相加？不同选择的第二项不同，得到的数列就不同，各类之间不会重复；所有合法的第二项也都列到了。

x=1 时，不能再加正整数，所以 f[1]=1。也可以统一令每个 f[x] 先等于 1，再把后面各项加上；x=1 时内层循环自然不执行。

| x | 计算 | f[x] |
| --- | --- | --- |
| 1 | 只有自身 | 1 |
| 2 | 1+f[1] | 2 |
| 3 | 1+f[1] | 2 |
| 4 | 1+f[1]+f[2] | 4 |
| 5 | 1+f[1]+f[2] | 4 |
| 6 | 1+f[1]+f[2]+f[3] | 6 |

### 方法一：从小到大递推

```cpp
#include<bits/stdc++.h>
using namespace std;

long long f[1005];

int main() {
    int n;
    cin >> n;

    for (int x = 1; x <= n; x++) {
        f[x] = 1;
        for (int next = 1; next <= x / 2; next++) {
            f[x] += f[next];
        }
    }

    cout << f[n] << '\n';
    return 0;
}
```

外层计算 f[x] 时，next 最大只有 x/2，比 x 小，因此 f[next] 已经算好。

两层循环总计不超过 n² 次，时间 O(n²)；n≤1000，代入后最多一百万这个量级，可以通过。数组空间 O(n)，用 long long 保存计数。

### 方法二：递归调用，算过的结果存起来

现在按照关系直接写 countWays(x)：先贡献 1，再递归求各个 countWays(next)。

为避免相同参数被重复展开，用 memo[x] 保存答案：

```cpp
#include<bits/stdc++.h>
using namespace std;

long long memo[1005];

long long countWays(int x) {
    if (memo[x] != 0) {
        return memo[x];
    }

    long long answer = 1;
    for (int next = 1; next <= x / 2; next++) {
        answer += countWays(next);
    }

    memo[x] = answer;
    return answer;
}

int main() {
    int n;
    cin >> n;
    cout << countWays(n) << '\n';
    return 0;
}
```

memo 定义在 main 外，初始都为 0。本题每个合法答案至少为 1，因此可以用 0 表示“还没算过”。

例如 countWays(6) 需要 countWays(1)、countWays(2)、countWays(3)。计算 countWays(2) 时又需要 countWays(1)，但 memo[1] 已经保存了 1，就直接返回，不再展开。

这叫**记忆化递归**，也常叫记忆化搜索。它仍是递归，只是为重复出现的同一个问题保存了答案。每个参数最多完整计算一次，因此这里总时间不超过 O(n²)，memo 数组空间 O(n)；调用时参数至少减半，调用栈深度为 O(log n)。

> **“没算过”标记要与合法答案区分。**
>
> 本题的答案不会为 0，所以 memo[x]=0 可以表示未计算。如果另一道题的合法答案可能是 0，就要另设 visited 数组，或者选用不会与答案重复的标记。
>
> 本题 x=1 时循环不执行，直接保存并返回 1，就是递归出口。找到出口时，要看实际执行过程，不一定非要出现一条单独的 if。

## 分治：把一个任务分成几个较小任务

递归还经常用来实现**分治**：拆分问题，分别处理，再组合结果。

例如要统计一段数组中有多少偶数，可以把它分成左右两半，分别统计，再把两边数量相加。只剩一个元素时，直接判断它是不是偶数。

```text
统计 [0, 8) 这 8 个数
├─ 统计 [0, 4)
└─ 统计 [4, 8)
两边结果相加
```

这里每个元素仍然要看一次，分治并没有减少总遍历量；它给出了另一种组织问题的方式。以后学习更复杂的算法时，还会遇到“拆分 → 递归处理 → 合并”的过程。

先记住：**递归是一种程序执行方式；分治是一种拆分问题的思路。** 走台阶中反复求同一个答案，则更适合把结果保存下来。
