## 递归：把较小的问题交给同一个函数

第一章学过函数。一个函数如果在执行过程中调用自己，就叫**递归**。

以阶乘为例：

```text
4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1 × 0!
0! = 1
```

计算 n! 时，只要知道 (n−1)!，再乘 n 就行；n=0 时直接返回 1，不再调用。这正好可以写成函数。

下面也是本地演示，输入范围为 `0 <= n <= 20`。20! 为 2432902008176640000，能放入 `long long`；21! 已超过有符号 64 位 `long long` 的范围。

把思路拆成两句话：“n=0 时答案就是 1；否则先算 (n−1)!，再乘 n。”于是代码分成出口判断、调用较小问题、组合结果三部分。递归调用的参数 n−1 来自这个关系；先理解要交给下一层什么任务，再决定怎样调用函数。

```cpp
#include<bits/stdc++.h>
using namespace std;

long long factorial(int n) {
    if (n == 0) {
        return 1;
    }
    long long smaller = factorial(n - 1);
    return n * smaller;
}

int main() {
    int n;
    cin >> n;
    cout << factorial(n) << '\n';
    return 0;
}
```

输入 `4`，输出 `24`。

### 调用之后，原来的函数在等什么

不要把递归想成程序突然重新开始。每次函数调用都有自己的参数和局部变量。

算 `factorial(3)` 时，调用过程可以这样画：

```text
进入 factorial(3)，n=3，等待 factorial(2)
    进入 factorial(2)，n=2，等待 factorial(1)
        进入 factorial(1)，n=1，等待 factorial(0)
            进入 factorial(0)，直接返回 1
        factorial(1) 得到 smaller=1，返回 1×1=1
    factorial(2) 得到 smaller=1，返回 2×1=2
factorial(3) 得到 smaller=2，返回 3×2=6
```

**调用时向更小的问题走，返回时把结果逐层交回来。** 外层函数没有消失，而是暂停在调用处，等结果回来后继续执行下一行。

### 出口与规模缩小

递归必须有两件事：

- **出口：** 哪些情况可以直接给出结果？阶乘的出口是 n=0。
- **向出口靠近：** 每次调用怎样让问题变小？这里是 n 变成 n−1。

如果漏写出口，或者一直调用 `factorial(n)`，函数就会不断调用下去。每一层调用还要占用保存现场的空间，这叫**调用栈**；层数过深会耗尽栈空间，出现 RE。

阶乘递归一共约 n 层，时间 $\mathcal{O}(n)$，调用栈空间 $\mathcal{O}(n)$。循环写阶乘只需要几个变量，额外空间可以是 $\mathcal{O}(1)$。

## 递推与递归：同一关系，两种计算方向

| 方法 | 从哪里开始 | 怎样推进 |
| --- | --- | --- |
| 递推 | 已知的初始值 | 按顺序算出更大的答案 |
| 递归 | 想求的目标 | 调用较小问题，等它返回后组合 |

同一个关系，常常既能写循环递推，也能写递归。但**递归不是“把循环换成函数”就一定更快**，还要看调用总次数。

比如直接写 `ways(n - 1) + ways(n - 2)` 求走台阶：

```text
ways(5)
├─ ways(4)
│  ├─ ways(3)
│  └─ ways(2)
└─ ways(3)  ← 又计算了一次
   ├─ ways(2)
   └─ ways(1)
```

相同的 `ways(3)`、`ways(2)` 会反复展开。直接递归的调用量按指数增长，可以用 $\mathcal{O}(2^{n})$ 作上界；上一节的递推只把每个 `f[i]` 算一次，是 $\mathcal{O}(n)$。

这引出一个很实用的办法：**把算过的答案记下来，下次直接取。** 后面会用数组实现它。


## 例题精讲：P1464 · Function

**原题：** [P1464 · Function](https://www.luogu.com.cn/problem/P1464)，来自[自编入门题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 按题目给定的规则计算递归函数 `w(a, b, c)`。有多组输入，读到三个 −1 时结束；每组按指定格式输出函数值。

输入参数可能达到 `long long` 的范围：−9223372036854775808 到 9223372036854775807，最多 10⁵ 组查询。因此先用 `long long` 读入，再按规则处理。

### 按顺序理解四条规则

规则按下面的先后顺序判断：

```text
1. a、b、c 中只要有一个 <= 0，返回 1。
2. 否则，只要有一个 > 20，返回 w(20, 20, 20)。
3. 否则，如果 a < b 且 b < c：
   w(a,b,c) = w(a,b,c-1) + w(a,b-1,c-1) - w(a,b-1,c)
4. 其他情况：
   w(a,b,c) = w(a-1,b,c) + w(a-1,b-1,c)
            + w(a-1,b,c-1) - w(a-1,b-1,c-1)
```

不必先背住公式。题目已经规定了函数怎样计算，我们的任务是把条件翻译成代码，并解决重复计算。

**第一条就是出口。** 在第 3、4 条中，每次调用都会让参数的总和变小，最终有参数降到 0，便开始返回。

条件顺序也有意义。例如 `w(30, -1, 0)`，先满足第一条，答案就是 1；不能先因为 30>20 就跳到第二条。

### 手算 w(1,1,1)

它的三个参数相等，不满足 a<b<c，使用第 4 条：

```text
w(1,1,1)
= w(0,1,1) + w(0,0,1) + w(0,1,0) - w(0,0,0)
= 1 + 1 + 1 - 1
= 2
```

四个子调用都因为有参数为 0 而直接返回 1。

算 `w(2, 2, 2)` 时，又会调用 `w(1, 2, 2)`、`w(1, 1, 2)`、`w(1, 2, 1)`、`w(1, 1, 1)`。这些调用展开后，有一些相同参数会反复出现。就像前面 `ways(3)` 被重复计算一样，我们应该把答案保存下来。

### 用三个下标保存“同一组参数”的答案

上一节用 `f[x]` 保存一个参数对应的答案。这里有 a、b、c 三个参数，就用：

```text
memo[a][b][c]
```

把它理解成“第 a 层、第 b 行、第 c 列的格子”。三个下标共同确定一个位置；只有 a、b、c **全部相同**，才是同一个子问题。

经过前两条规则后，需要展开的参数都在 1 到 20 内。开 `memo[21][21][21]` 就够用，合法下标为 0 到 20，一共 9261 个格子。**输入很大，不代表要按输入原值开一个巨大数组。** 先按题目规则缩小参数，再访问记忆数组。

另外用 `visited[a][b][c]` 记录这格是否已经算过：

- 已经算过：直接返回 memo 中的值。
- 没有算过：递归求出结果，存入 memo，并标记 `visited = true`。

这样每组参数只会完整展开一次，就是**记忆化递归**，也常叫记忆化搜索。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

long long memo[21][21][21];
bool visited[21][21][21];

long long w(long long a, long long b, long long c) {
    if (a <= 0 || b <= 0 || c <= 0) {
        return 1;
    }
    if (a > 20 || b > 20 || c > 20) {
        return w(20, 20, 20);
    }
    if (visited[a][b][c]) {
        return memo[a][b][c];
    }

    long long ans;
    if (a < b && b < c) {
        ans = w(a, b, c - 1) + w(a, b - 1, c - 1)
            - w(a, b - 1, c);
    } else {
        ans = w(a - 1, b, c) + w(a - 1, b - 1, c)
            + w(a - 1, b, c - 1) - w(a - 1, b - 1, c - 1);
    }

    memo[a][b][c] = ans;
    visited[a][b][c] = true;
    return ans;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    long long a, b, c;
    while (cin >> a >> b >> c) {
        if (a == -1 && b == -1 && c == -1) {
            break;
        }
        printf("w(%lld, %lld, %lld) = %lld\n", a, b, c, w(a, b, c));
    }
    return 0;
}
```

输入：

```text
1 1 1
2 2 2
30 -1 0
21 21 21
-1 -1 -1
```

输出：

```text
w(1, 1, 1) = 2
w(2, 2, 2) = 4
w(30, -1, 0) = 1
w(21, 21, 21) = 1048576
```

### 把容易漏掉的细节对照一遍

- **先检查出口和参数范围，再访问数组。** 负数或很大的参数不能直接当下标。
- 只有三个参数**同时等于 −1**才结束，单独有一个 −1 仍然要计算。
- memo 和 visited 放在 main 外，初始分别为 0、false，多组查询共用。函数定义不变，同一组参数的答案也不变，不用每次清空。
- 打印的是输入原来的 a、b、c。例如输入 21、21、21，虽然内部转换为 `w(20, 20, 20)`，输出括号里仍写 21。
- `printf` 的四个 `%lld` 分别对应三个输入参数和返回的答案，逗号后有空格。这里输入全用 `cin`，输出全用 `printf`。

最多只有 20³ 组正参数需要展开，每组做固定次数的子调用；算过后直接取值。T 次查询的总时间可记为 **$\mathcal{O}(20^{3}+T)$**，记忆数组空间 $\mathcal{O}(20^{3})$。

正常展开时 a+b+c 每次都会减小，所以递归只有几十层。这里同时检查了两件事：**总共展开多少个不同问题，以及一条调用链有多深。**

## 分治：把一个任务分成几个较小任务

递归还经常用来实现**分治**：拆分问题，分别处理，再组合结果。

例如要统计一段数组中有多少偶数，可以把它分成左右两半，分别统计，再把两边数量相加。只剩一个元素时，直接判断它是不是偶数。

```text
统计 [0, 8) 这 8 个数
├─ 统计 [0, 4)
└─ 统计 [4, 8)
两边结果相加
```

这里每个元素仍然要看一次，分治并没有减少总遍历量；它给出了另一种组织问题的方式。以后学习更复杂的算法时，还会遇到“拆分 → 递归处理 → 合并”的过程。

先记住：**递归是一种程序执行方式；分治是一种拆分问题的思路。** 走台阶中反复求同一个答案，则更适合把结果保存下来。
