## 为什么可以每次排除一半

先看已经升序排列的一组数：

```text
编号：1  2  3  4  5  6  7
数值：1  2  2  2  5  7  9
```

要找数字 7，先看中间的第 4 个数，它是 2。因为数组有序，前 4 个数都不会大于 2，所以不可能是 7，可以一起排除。

只需要继续在第 5 到第 7 个数中查找，再取中点、再排除一半。这就是**二分查找**。

n 个数大约只需要 log₂n 轮；一百万个数，减半约 20 次就能缩到很小的范围。

有序性是这里的依据。若数组是乱的，中间的数小于目标，并不能说明它左边都小于目标。

## 闭区间与 ans：每个变量都有直接的含义

本节把数据存放在 a[1] 到 a[n]，使用：

```text
int le = 1, r = n, ans = -1;
```

- **le：** 当前还要查找的最左编号。
- **r：** 当前还要查找的最右编号。
- **[le,r]：** 两端都包含，还没有检查完的位置。
- **ans：** 目前已经找到的答案，−1 表示还没找到。

只要 `le <= r`，范围里就还有元素，可以继续：

```text
while (le <= r) {
    int mid = le + (r - le) / 2;
    // 检查 a[mid]，再排除 mid 和一侧的位置
}
```

le=r 时只剩一个元素，也要检查，所以这里有等号。le>r 时，范围已经空了，结束循环，直接返回 ans。

中点写成 `le + (r - le) / 2`，可以避免 le+r 太大时溢出；它与本题范围内的 `(le + r) / 2` 得到相同结果。

> **答案存进 ans，mid 检查后就排除。**
>
> 向右继续找：le=mid+1；向左继续找：r=mid−1。
>
> 每轮都把已经检查过的 mid 排除，不再使用 le=mid 或 r=mid 的写法。循环结束后直接使用 ans。

## 重复值：找到之后，继续向左找

题目有时要求**目标第一次出现的编号**。例如这组数里的 2，出现在第 2、3、4 个位置。

若中点正好是第 4 个数，我们已经找到了一个 2，可以先记录 `ans=4`。但它前面可能还有 2，所以继续向左找：

```text
ans = mid;
r = mid - 1;
```

把 mid 排除不会丢答案，因为它已经保存在 ans 中了。后面如果找到更靠左的相等值，就用新的编号更新 ans。

三种情况可以直接列成表：

| a[mid] 与目标 x 的关系 | 怎样处理 | 接下来找哪里 |
| --- | --- | --- |
| a[mid]<x | 左边都太小，不能是答案 | le=mid+1 |
| a[mid]>x | 右边都太大，不能是答案 | r=mid−1 |
| a[mid]=x | ans=mid，先保存这一答案 | r=mid−1，继续找更早的 |

### 把动图过程记成表

找 x=2：

| 轮次 | le | r | mid | a[mid] | 本轮操作 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 7 | 4 | 2 | ans=4，r=3 |
| 2 | 1 | 3 | 2 | 2 | ans=2，r=1 |
| 3 | 1 | 1 | 1 | 1 | le=2，ans 保留 2 |

最后 le=2、r=1，循环结束。**不用从两个边界推算答案，直接输出 ans=2。**

若要找最后一次出现的位置，找到相等值后改为向右继续找：先 `ans=mid`，再 `le=mid+1`。先想清楚“还有没有更好的位置在左边或右边”，再决定方向。

## 例题精讲：P2249 · 查找

**原题：** [P2249 · 查找](https://www.luogu.com.cn/problem/P2249)，来自[优先参考题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 给出已经单调不减的数组，进行 m 次询问。每次输出目标第一次出现的编号，从 1 开始；不存在就输出 −1。n≤10⁶，m≤10⁵，数组值和查询值在 0 到 10⁹ 之间。

单调不减允许相等，题目已经保证有序，不需要再排序。

### 为什么不能每次从头扫描

每次最多看 n 个数，m 次是 O(nm)，代入最大规模为 10¹¹，计算量过大。

每次二分只需要 O(log n)，m 次约两百万轮判断。加上读入数组，总时间为 O(n+m log n)，数组空间 O(n)。

### 输入输出示例

输入：

```text
5 5
1 2 2 2 5
2 4 1 6 5
```

输出：

```text
2 -1 1 -1 5
```

查 2 时，记录找到的编号，继续向左找，最后保留 2。查 4 时，所有候选位置都被排除，ans 没有更新，仍为 −1。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int a[1000005];

int findFirst(int n, int x) {
    int le = 1, r = n, ans = -1;
    while (le <= r) {
        int mid = le + (r - le) / 2;
        if (a[mid] == x) {
            ans = mid;
            r = mid - 1;
        } else if (a[mid] < x) {
            le = mid + 1;
        } else {
            r = mid - 1;
        }
    }
    return ans;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    for (int i = 0; i < m; i++) {
        int x;
        cin >> x;
        if (i > 0) cout << ' ';
        cout << findFirst(n, x);
    }
    cout << '\n';
    return 0;
}
```

### 检查一次边界与返回值

- 本节是 1 下标，初始范围为 [1,n]，因此 mid 总是一个合法的数据位置。
- ans=−1 表示没找到；相等时记录的是题目要求的原编号。
- 找到后继续向左，ans 只会换成更早的相等位置。
- 每轮更新都越过 mid，范围一定缩小；只剩一个数时也能正确结束。
- 最后返回 ans。数组元素最多一百万，关闭 cin 流同步后再读入。

## lower_bound 与 upper_bound

理解手写二分后，可以使用标准库直接完成常见查找。

本节仍把数据存放在 a[1] 到 a[n]：

```text
int pos = lower_bound(a + 1, a + n + 1, x) - a;
```

lower_bound 找第一个**大于或等于 x**的位置。返回的位置减去数组开头 a，就得到本节使用的 1 下标。

这里库函数的两个参数与 sort 一样，表示从开头到结尾之前，也就是 [a+1,a+n+1)。这是**标准库接口的区间约定**；我们前面手写二分的待查范围仍然是闭区间 [le,r]。

如果所有数都小于 x，pos 会等于 n+1。要判断 x 是否存在，先检查位置，再读数组：

```text
if (pos <= n && a[pos] == x) {
    // 找到了，编号是 pos
}
```

&& 先计算左边，左边为假就不再计算右边，避免访问本次数据范围之外的位置。

upper_bound 找第一个**严格大于 x**的位置：

```text
int pos = upper_bound(a + 1, a + n + 1, x) - a;
```

| 函数 | 返回的位置 |
| --- | --- |
| lower_bound | 第一个 ≥x |
| upper_bound | 第一个 >x |

对 1、2、2、2、5 查找 2，lower_bound 得到 2，upper_bound 得到 5。所有 2 都在编号 2、3、4，出现次数为 5−2=3：

```text
int first = lower_bound(a + 1, a + n + 1, x) - a;
int after = upper_bound(a + 1, a + n + 1, x) - a;
int count = after - first;
```

x 不存在时，两者落在同一个插入位置，差为 0。单次调用在数组上为 O(log n)。

> **标准库查找前，先保证数组升序。**
>
> 无序数组先用 sort。题目如果要求保留原输入顺序或编号，要先保存记录，再决定排序哪份数据。
>
> 使用库函数返回的位置时检查范围；手写闭区间查找则直接返回自己维护的 ans。
