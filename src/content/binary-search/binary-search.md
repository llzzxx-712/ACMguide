## 为什么每次可以排除一半

有一组已经升序排列的数：

```text
下标：0  1  2  3  4  5  6
数值：1  3  5  7  9 11 13
```

要找 11，可以先看中间的 7：

- 7<11，因为数组有序，7 左边的数也不可能是 11。
- 只需要继续在右边查找。
- 再看剩余部分的中间，重复这个过程。

这就是**二分查找**：利用有序性，每次排除约一半候选范围。

n 个数大约只需要 log₂n 轮。n=10⁶ 时，减半约 20 次就能缩到一个位置。

如果数组没排好，仅仅知道“中间的数小于目标”，并不能推出左边都小于目标。因此使用二分前，先确认当前查找的顺序满足要求。

## 找到一个相等值，还不一定完成题目

假设数组为：

```text
1 2 2 2 5
```

找数字 2 时，下标 1、2、3 都相等。若题目要求第一次出现的位置，找到中间的 2 就立即返回，会漏掉它前面的 2。

我们换一个更明确的目标：

**找第一个大于或等于 x 的位置。**

对 x=2，判断每个位置的 `a[i] >= x`，结果是：

```text
数值：1  2  2  2  5
判断：否 是 是 是 是
         ↑ 第一个“是”
```

对 x=4：

```text
数值：1  2  2  2  5
判断：否 否 否 否 是
                  ↑ 第一个“是”
```

如果这个位置上的数恰好等于 x，它就是 x 第一次出现的位置；如果不等于，数组中就没有 x。

二分查找现在变成了**寻找“否 → 是”的分界位置**。

## 统一使用左闭右开的范围

本节数组下标为 0 到 n−1，使用两个变量：

```text
left = 0;
right = n;
```

查找范围写成 **[left,right)**：包含 left，不包含 right。这与上一章 sort 的区间写法相同。

在整个过程中，我们始终保持：

- 下标小于 left 的元素，都已经确定小于 x。
- 下标大于或等于 right 的现有元素，都已经确定大于或等于 x。
- 还没处理的元素在 [left,right) 内。

这条在循环前后都保持的事实，叫**循环不变量**。先把它理解成“每一轮都不改变的边界含义”。

### 中点与两种更新

只要 left<right，区间里还有元素，取中点：

```text
int mid = left + (right - left) / 2;
```

相较于 `(left + right) / 2`，这样写可以避免 left+right 过大时的整数溢出。

然后判断：

| 中点情况 | 已经知道什么 | 更新 |
| --- | --- | --- |
| a[mid]<x | mid 及其左侧都小于 x | left=mid+1 |
| a[mid]>=x | mid 及其右侧都大于或等于 x | right=mid |

第二种情况下，mid 可能就是第一个满足条件的位置。我们把它划入“已经满足条件”的右侧，让 right 保留这个位置；接下来只需要继续检查它前面有没有更早的。

注意：**right 代表已知右侧的起点，最后也可以成为返回的位置**，不是把 mid 的答案资格丢掉。

### 完整地手算一次

数组为 1、2、2、2、5，查 x=2：

| 轮次 | left | right | mid | a[mid] | 更新 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | 5 | 2 | 2 | right=2 |
| 2 | 0 | 2 | 1 | 2 | right=1 |
| 3 | 0 | 1 | 0 | 1 | left=1 |

现在 left=right=1，未处理区间为空。下标 1 前面的数都小于 2，从下标 1 开始的数都不小于 2，所以答案位置就是 1。

把目标换成 6，最后会得到 left=n=5，表示**所有数都小于 6，数组里没有大于或等于 6 的元素**。n 是“末尾之后”的位置，不能读取 a[n]。

> **先判断位置有效，再访问数组。**
>
> 查找结果可能为 n。判断目标是否存在时，按这个顺序写：
>
> `pos < n && a[pos] == x`
>
> C++ 的 && 会先算左边；左边为假时，不再访问右边。这样就不会去读不属于本次数据范围的 a[n]。

## 例题精讲：P2249 · 查找

**原题：** [P2249 · 查找](https://www.luogu.com.cn/problem/P2249)。

**题意简述：** 给出一个已经单调不减的数组，进行 m 次询问。每次输出目标第一次出现的编号，编号从 1 开始；不存在就输出 −1。n≤10⁶，m≤10⁵，数组值和查询值在 0 到 10⁹ 之间。

“单调不减”就是后面的数不小于前面，允许相等。题目已经给出有序数组，不需要再排序。

### 为什么不能每次从头扫描

每次扫描最多 n 个数，m 次就需要 O(nm)。把最大规模代入，是 10⁶×10⁵=10¹¹，计算量过大。

改成每次二分，只需要 O(log n)，全部查询为 O(m log n)，大约两百万轮判断。加上读入数组，总时间为 O(n+m log n)。

### 输入输出示例

输入：

```text
5 5
1 2 2 2 5
2 4 1 6 5
```

输出：

```text
2 -1 1 -1 5
```

以目标 2 为例，二分返回下标 1，题目要求从 1 开始的编号，所以输出 1+1=2。

目标 4 的查找结果为下标 4，但 a[4]=5，不等于 4，输出 −1。目标 6 返回 n，也输出 −1。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int a[1000005];

int firstAtLeast(int n, int x) {
    int left = 0, right = n;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] < x) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }
    return left;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    for (int i = 0; i < m; i++) {
        int x;
        cin >> x;
        int pos = firstAtLeast(n, x);

        if (i > 0) cout << ' ';
        if (pos < n && a[pos] == x) {
            cout << pos + 1;
        } else {
            cout << -1;
        }
    }
    cout << '\n';
    return 0;
}
```

### 为什么不会死循环

left<right 时，mid 一定满足 left≤mid<right：

- 更新 left=mid+1，左边界一定向右移动。
- 更新 right=mid，右边界一定向左移动。

所以未处理区间每次都会缩小。若把第一种更新误写为 left=mid，区间只剩一个元素时，mid 可能等于 left，边界就会原地不动。

**循环条件、区间含义和更新方式是一套配合使用的写法。** 先理解这套，再自己逐轮运行，不要把另一套区间的某行更新直接替换进来。

本题数组空间是 O(n)，每次二分只需要几个变量，额外查找空间 O(1)。

## 用 lower_bound 直接找到同一个位置

C++ 已经提供了实现：

```text
int pos = lower_bound(a, a + n, x) - a;
```

- 在升序的 a[0] 到 a[n−1] 中查找。
- lower_bound 返回第一个大于或等于 x 的位置。
- `- a` 计算它距离数组开头有多少个元素，也就是 0 下标。
- 没有满足条件的元素时，返回末尾位置 a+n，减去 a 后得到 n。

这里的“位置减开头”，先理解为算距离即可。得到的结果可以直接赋给 int，因为本题下标在 int 范围内。

把例题中的 `firstAtLeast(n, x)` 换成这行调用，后面的范围检查与输出完全一样。

## upper_bound：找第一个严格大于 x 的位置

另一个常用函数是：

```text
int rightPos = upper_bound(a, a + n, x) - a;
```

两者的区别只在于有没有等号：

| 函数 | 找到的位置 |
| --- | --- |
| lower_bound | 第一个 ≥x |
| upper_bound | 第一个 >x |

对 1、2、2、2、5 查找 2：

```text
下标：0  1  2  3  4
数值：1  2  2  2  5
         ↑        ↑
       lower     upper
```

lower=1，upper=4，所有 2 都在 [1,4) 内。因此 2 出现了 4−1=3 次：

```text
int leftPos = lower_bound(a, a + n, x) - a;
int rightPos = upper_bound(a, a + n, x) - a;
int count = rightPos - leftPos;
```

若 x 不存在，两者会落在同一个插入位置，差为 0。例如查 4，两者都是 4；查 6，两者都是 n。

单次 lower_bound、upper_bound 在数组上的时间复杂度都是 O(log n)。

> **先排好序，再用这两个函数。**
>
> 本节统一在升序数组上使用默认的 lower_bound、upper_bound。无序数组先用 sort。
>
> 如果题目要求保留原输入顺序或原编号，先保存记录，再决定哪一份数据用于排序；不要为了二分把后续还要用的顺序改乱。
