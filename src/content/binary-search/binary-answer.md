## 从“直接求最优”改成“这个值能不能做到”

上一节，数组中小于 x 的元素在前，大于或等于 x 的元素在后，我们找到它们的分界。

现在考虑一个新问题：锯片设置得越高，锯下来的木材越少。如果需要至少 7 米木材，怎样找到锯片能设置的最高位置？

直接问“最高是多少”，可能还没思路。但给定一个具体高度，例如 15 米，就很好判断：逐棵计算能锯下多少，加起来是否达到 7 米。

这一步很关键：

**把求最优值，改成判断某个值是否可行。**

然后观察：可行性会不会随着候选值的增大，只在一个方向上变化？如果会，就有机会二分。

## 例题精讲：P1873 · 砍树

**原题：** [P1873 · 砍树](https://www.luogu.com.cn/problem/P1873)。

**题意简述：** 有 N 棵树，需要至少 M 米木材。把锯片设在整数高度 H，所有高于 H 的树都会被锯下高出的部分。求能够取得足够木材的最大 H。

数据范围：N≤10⁶，M≤2×10⁹，树高不超过 4×10⁵；题目保证全部树高之和大于 M。

输入：

```text
4 7
20 15 10 17
```

输出：

```text
15
```

### 固定高度后，怎样检查

若一棵树高 h：

- h>H，锯下 h−H。
- h≤H，锯不到木材，贡献 0。

所以对所有树求和即可。

| 锯片 H | 高 20 的树 | 高 15 的树 | 高 10 的树 | 高 17 的树 | 总木材 | 至少 7 米？ |
| --- | --- | --- | --- | --- | --- | --- |
| 14 | 6 | 1 | 0 | 3 | 10 | 是 |
| 15 | 5 | 0 | 0 | 2 | 7 | 是 |
| 16 | 4 | 0 | 0 | 1 | 5 | 否 |

因此 H=15 可行，H=16 已不可行，最高能设到 15。

我们把“高度 H 能否取得足够木材”封装成一个 bool 函数 check(H)。返回 true 表示可行，false 表示不可行。

## 单调性：为什么能二分答案

锯片升高时，每棵树能贡献的木材只会减少或不变，总量也只会减少或不变。

因此：

- 如果 H 可行，比 H 更低的高度也可行。
- 如果 H 不可行，比 H 更高的高度也不可行。

把所有候选整数高度从小到大排列：

```text
高度：0  1  2  ...  14 15 16 17 ... 最高树高
可行：是 是 是 ...  是 是 否 否 ...    否
                        ↑
                   最后一个“是”
```

这种“是 → 否，只切换一次”的性质，就是本题的**单调性**。答案是最后一个可行高度。

树的输入顺序可以是乱的。这里有序的是**候选高度对应的可行性**，不需要给树排序。

> **二分答案前，先说清楚单调方向。**
>
> 不要只看到“最大”“最小”就写二分。先固定一个候选值，说明怎样判断它；再说明候选值变大后，判断结果为什么只会向一个方向变化。
>
> 砍树中，高度越大，取得的木材越少，所以可行高度在左，不可行高度在右。

## 沿用上一节：寻找第一个“不可以”

上一节找的是“第一个大于或等于 x 的位置”。现在仍然寻找分界，只是右侧的条件变成了“高度不可行”。

先找**第一个不可行高度**，它减 1，就是最后一个可行高度。

范围取：

```text
left = 0;
right = 最高树高;
```

为什么这样取？

- H=0 时，能取得所有树的高度总和，题目保证它大于 M，所以一定可行。
- H=最高树高时，一点木材也取不到，而 M≥1，所以一定不可行。
- 因此分界一定存在于这个范围中。

与昨天一样，待检查的候选值在 [left,right) 中；小于 left 的高度已经确定可行，right 及以上的高度已经确定不可行。

取 mid 后：

| check(mid) | 能排除哪些高度 | 更新 |
| --- | --- | --- |
| true，可行 | mid 以及更低的都可行 | left=mid+1 |
| false，不可行 | mid 以及更高的都不可行 | right=mid |

循环结束时 left=right，是第一个不可行高度；答案为 left−1。

### 用样例跟踪每一轮

| 轮次 | left | right | mid | 木材总量 | 更新 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | 20 | 10 | 22 | 可行，left=11 |
| 2 | 11 | 20 | 15 | 7 | 可行，left=16 |
| 3 | 16 | 20 | 18 | 2 | 不可行，right=18 |
| 4 | 16 | 18 | 17 | 3 | 不可行，right=17 |
| 5 | 16 | 17 | 16 | 5 | 不可行，right=16 |

退出时 left=16，返回 16−1=15。

表中为方便理解，列出全部树的木材总量。代码里一旦发现累计已经达到 M，就可以提前返回 true，不必继续把这一轮所有树都算完。

## 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int n;
int height[1000005];
long long need;

bool check(int cut) {
    long long wood = 0;
    for (int i = 0; i < n; i++) {
        if (height[i] > cut) {
            wood += height[i] - cut;
        }
        if (wood >= need) {
            return true;
        }
    }
    return false;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> need;
    int highest = 0;
    for (int i = 0; i < n; i++) {
        cin >> height[i];
        highest = max(highest, height[i]);
    }

    int left = 0, right = highest;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (check(mid)) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }

    cout << left - 1 << '\n';
    return 0;
}
```

### 哪些地方容易写错

**1. 每次 check 都要重新统计。**

wood 定义在 check 内，初始为 0。每次试新的锯片高度，都要重新计算这一高度能得到多少木材，不能沿用上一次的累计值。

**2. 不高于锯片的树贡献为 0。**

只有 height[i]>cut 时才相加；否则直接加 height[i]−cut，会把负数加进去。

**3. 判断是“大于或等于所需木材”。**

刚好达到 M 就可行，用 `wood >= need`。目标是“至少 M”，不是“恰好 M”。

**4. 累计值用 long long。**

单棵树高能放在 int 中，但最多一百万棵树，总量可达 4×10¹¹，超过 int 的 2147483647。wood 与 need 使用 long long，累加过程就在 long long 中完成。

**5. 想清楚退出后变量表示什么。**

这里的 left 是第一个不可行高度，所以输出 left−1。不要看到“退出后 left=right”就习惯性直接输出 left。

> **check 只回答是否可行。**
>
> 不要在 check 中永久修改树高，否则下一次检查的就不是原来的输入了。
>
> 本题 check 每次从原数组读取数据、用局部变量累计；无论先试哪个高度，同一个高度都会得到同样的判断结果。

## 算一次完整复杂度

一次 check 最多看 n 棵树，是 O(n)。

候选高度范围为 0 到 Hmax，二分进行 O(log(Hmax+1)) 轮，因此总时间为：

```text
O(n log(Hmax + 1))
```

把 n=10⁶、Hmax=4×10⁵ 代入，大约是 19 轮检查，也就是一千九百万这个量级的处理。数组空间 O(n)，check 的额外空间 O(1)。

**二分只有对数轮，但每轮 check 也有成本。** 如果 check 写成了两层大循环，就要把这部分复杂度一起乘进去。

## 换个方向：最小可行值

砍树要找最大可行值，可行性是：

```text
是 是 是 是 | 否 否 否
```

还有一些题目问“最小容量”“最小的最大段和”。候选值越大，限制越宽松，可行性可能是：

```text
否 否 否 | 是 是 是 是
```

这种情况直接找第一个可行值，与上一节找第一个 ≥x 的位置相同：

```text
while (left < right) {
    int mid = left + (right - left) / 2;
    if (check(mid)) {
        right = mid;
    } else {
        left = mid + 1;
    }
}
```

使用前要选好上下界，并让 right 是一个确定可行的值。退出时 left 就是第一个可行值，不需要再减 1。

| 题目目标 | 从小到大的可行性 | 寻找的分界 | 返回 |
| --- | --- | --- | --- |
| 最大可行值 | 是 → 否 | 第一个不可行值 | 分界−1 |
| 最小可行值 | 否 → 是 | 第一个可行值 | 分界 |

它们都在找一个“前后性质不同”的分界。先判断方向，再决定 true 时移动哪一边。

## 练习：自己写出 check 的含义

先关闭代码，独立完成 [P1873 · 砍树](https://www.luogu.com.cn/problem/P1873)。在纸上写出 check(H) 的含义、单调方向、初始边界，以及退出后为什么减 1。测试只含一棵树、答案为 0、刚好取得所需木材、所有树等高，以及总木材超过 int 的情况。

### 推荐必做

1. [P2440 · 木材加工](https://www.luogu.com.cn/problem/P2440)：把原木切成至少 k 段等长的整数长度小段，求最大长度。固定长度 len 后，一根原木能切出 `length / len` 段，累加段数即可判断。**从正长度 1 开始检查，不能把 0 送入除法。** 可把 maxLength+1 当作确定不可行的右边界，找第一个不可行长度后减 1；若 1 都不可行，答案自然为 0。段数累计用 long long。

### 选做：需要继续巩固时练习

1. [P1182 · 数列分段 Section II](https://www.luogu.com.cn/problem/P1182)：把数列分成 M 个连续非空段，让最大段和最小。固定上限 limit 后，从左往右尽量往当前段放，放不下就开新段；需要的最少段数≤M 时可行。上界取全体元素之和，下界取最大元素，累计和用 long long。因为元素非负，少于 M 段时可以继续拆成 M 段，不会让最大段和增加。
2. [P3853 · 路标设置](https://www.luogu.com.cn/problem/P3853)：最多增加 K 个路标，让相邻路标的最大距离最小。固定允许距离 d≥1，一段原有间隔 gap 至少需要新增 `(gap - 1) / d` 个路标；累加所需数量，与 K 比较。先用 gap=10、d=5 验证为什么是 gap−1，再确定最小可行值的单调方向。
