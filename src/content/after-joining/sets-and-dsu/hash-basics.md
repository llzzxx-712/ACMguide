## 这一节学什么

如果只想知道一个字符串以前是否出现过，并不需要按字典序找到它的位置。哈希表会先计算一个编号，快速缩小查找范围。本节讲清哈希、桶、冲突与相等判断，再把它们用于去重。

>

## 先算编号，再去对应位置找

假设有很多写着姓名的卡片，逐张比较很慢。我们可以先按某个规则计算桶编号，把卡片放到对应桶中；查询时只检查这个桶。

一个用于观察过程的简单规则是：把字符串中字符的 ASCII 编码求和，再对 10 取余。

```text
"ab"：97+98=195，放入 5 号桶
"ba"：98+97=195，也放入 5 号桶
"ac"：97+99=196，放入 6 号桶
```

这个“从内容计算编号”的过程叫**哈希**。上面的规则方便手算，但容易把不同字符串放到一起；先用它看清执行过程。

## 冲突之后，仍要判断内容是否相等

ab 和 ba 的桶编号相同，字符串却不同，这叫**哈希冲突**。桶只是缩小范围的线索，不能直接代表字符串本身。

```text
5 号桶：ab → ba
6 号桶：ac

查询 ba：先找到 5 号桶
         与 ab 比较，不同
         与 ba 比较，相同，找到

查询 bb：先计算桶编号，再检查对应桶
```

一种处理方式是在同一个桶里保存多个成员，查询时继续比较原内容。**哈希值相同，不代表对象相同。** 如果只把一个计算出的整数存起来去重，碰到冲突就可能错误地把两个不同字符串当成同一个。

## 使用 unordered_set 保存真正的字符串

`unordered_set<string>` 会保存字符串本身，内部利用哈希值定位，并在需要时比较字符串是否相等。

```text
unordered_set<string> seen;
seen.insert("ab");
seen.insert("ba");
seen.insert("ab");
int count = seen.size(); // count=2
```

标准容器中的哈希冲突可能增加查找代价，但不会让 ab 与 ba 因为桶相同就被当成一个字符串。

| 操作 | 含义 |
| --- | --- |
| `seen.insert(s)` | 插入字符串，已经存在则不增加成员 |
| `seen.count(s)` | 存在返回 1，否则返回 0 |
| `seen.find(s)` | 返回成员位置，找不到则返回 `end()` |
| `seen.erase(s)` | 删除这个字符串 |
| `seen.clear()` | 清空成员，方便处理下一组数据 |

`unordered_set` 不维护字典序，遍历顺序不能当成排序结果，也不能用来恢复输入顺序。需要保留第一次出现的顺序时，按输入顺序扫描，只在“以前没出现过”时输出或放入 `vector`。

### 平均复杂度与字符串长度

对固定大小的键，哈希表操作的平均时间为 $\mathcal{O}(1)$；大量成员进入相同桶时，单次操作可能退化为 $\mathcal{O}(n)$。对长度为 $L$ 的字符串，计算哈希通常还要读取 $L$ 个字符，因此不能忽略字符串本身的长度。

与二叉搜索树的高度分析一样，复杂度来自执行过程：桶分布影响需要检查的成员数，字符串长度影响一次比较和哈希计算的代价。

## 例题精讲：P3370 · 字符串哈希

**原题：** [P3370 · 字符串哈希](https://www.luogu.com.cn/problem/P3370)。

**题意简述：** 给出 $n$ 个由数字、大小写字母构成的字符串，区分大小写，输出不同字符串的数量。$n\le 10000$，单个字符串最长 1500。

本节使用标准库哈希表保存原字符串，练习“计算位置、判断是否已经出现、只保留一份”的过程。后续字符串算法章节会继续实现字符串哈希与子串比较。

自拟输入：

```text
5
ab
ba
ab
AB
ba
```

输出：

```text
3
```

### 从思路到代码

按输入顺序考虑：ab 首次出现，集合大小变为 1；ba 首次出现，变为 2；第二个 ab 已有，不变；AB 与 ab 大小写不同，变为 3；最后的 ba 已有，不变。

所以不需要另写一个计数变量，也不需要两两比较全部字符串。把每个字符串插入集合，最后读取集合大小即可。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    unordered_set<string> seen;
    seen.reserve(n * 2);
    for (int i = 0; i < n; i++) {
        string s;
        cin >> s;
        seen.insert(s);
    }
    cout << seen.size() << '\n';
    return 0;
}
```

reserve 提前准备容纳成员的空间，减少反复扩容；它不会提前插入字符串，调用后 size 仍为 0。

设所有输入字符串的总长度为 $S$。按哈希表平均操作代价估算，总时间 $\mathcal{O}(S+n)$，保存原字符串的空间 $\mathcal{O}(S+n)$。本题总字符数最多约 1500 万，输入量较大，因此程序在输入前关闭 `cin` 流同步。

## 练习：判断成员与保留顺序

先**独立重做 P3370**，覆盖完全相同、大小写不同、包含数字和长字符串的情况。

### 推荐必做

1. [P4305 · 不重复数字](https://www.luogu.com.cn/problem/P4305)：保留每个数第一次出现的位置顺序，有多组数据。用 `unordered_set<int>` 判断是否出现过，按读入顺序保存结果；每组重新建立或清空容器。

### 选做巩固

- [P1059 · 明明的随机数](https://www.luogu.com.cn/problem/P1059)：去掉重复数字并按升序输出。先用集合识别不同的数，再对收集的结果排序，比较保存出现顺序与输出升序的不同。
- [P1097 · 统计数字](https://www.luogu.com.cn/problem/P1097)：统计每个不同自然数出现的次数，按数值从小到大输出。用哈希映射累计次数，再将不同键排序，练习计数与输出顺序分工。
