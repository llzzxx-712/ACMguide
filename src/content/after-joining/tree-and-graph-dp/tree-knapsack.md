## 这一节学什么

上一节固定父点状态后，孩子答案可以直接相加。现在增加一个要求：整棵树只能选固定数量的点。给第一个孩子多分一个名额，别的孩子就会少一个，因此不能让每个孩子各自选到最好后直接相加。

树形背包解决的就是这个分配问题：**先算出每个孩子“分到不同名额时，最多能拿多少收益”，再逐个决定名额怎样分。**

> **AI 伴学提示词**
>
> 为我用选课手算树形背包，逐个合并孩子的名额与收益表，解释虚拟根、不可达和新旧数组，再对照循环引导我提问。

## 例题精讲：P2014 · 选课

**原题：** [P2014 · 选课](https://www.luogu.com.cn/problem/P2014)。

**题意简述：** n 门课程，每门有一门或没有直接先修课，选择课程就必须选择它的全部先修课程。恰好选 m 门，求最大学分。n,m≤300，课程安排无环，每门学分为 1…20。

输入：

```text
5 3
0 3
1 4
1 7
0 5
4 6
```

输出 `15`。每行给的是“直接先修课编号、学分”，画出依赖关系：

```text
课程 1（3 分）             课程 4（5 分）
├── 课程 2（4 分）         └── 课程 5（6 分）
└── 课程 3（7 分）
```

选 1、3、4，学分为 3+7+5=15。只选 3、4、5 看似有 18 分，却没有选课程 3 的先修课 1，不能作为合法方案。

## 第一步：先给每个子树做一份“方案菜单”

对课程 1 的子树，不要只问“最多能拿多少分”，而要分别问：

| 在这棵子树里选几门 | 最佳选择 | 学分 |
| --- | --- | --- |
| 0 | 全部不选 | 0 |
| 1 | 只选 1 | 3 |
| 2 | 选 1、3 | 10 |
| 3 | 选 1、2、3 | 14 |

对于父亲来说，这张表就足够了。它只关心分给这棵子树几门课的名额、能换回多少分，子树内部具体怎样选已经由孩子解决。

这与分组背包很接近：**每个孩子是一组方案，从这一组中选择一个“数量、收益”组合。** 选择 0 门也算一个方案，表示这个孩子整棵不选。不能同时拿这张表的“选 1 门”和“选 2 门”，那样会把同一棵子树重复使用。

## 第二步：用虚拟根统一多棵树

课程 1、4 都没有先修课。新增 0 号虚拟课程，学分为 0，让所有没有先修课的课程成为它的孩子：

```text
0（0 分）
├── 1（3 分）
│   ├── 2（4 分）
│   └── 3（7 分）
└── 4（5 分）
    └── 5（6 分）
```

以后统一要求“只要从 u 子树选课，就先选 u”。对 0 也照做，相当于额外选一门 0 分课程。原题选 3 门，因此最后在 0 子树里选 **4 个点**；一般答案为 f[0][m+1]。

## 第三步：给状态和初值写准含义

f[u][j] 表示从 u 子树中恰好选 j 个点的最大学分，**j>0 时必须包含 u**；f[u][0]=0 表示整棵子树不选。先修关系沿父子边向上延伸，所以每层都保留父点，就能保留全部先修课。

计算 u 时还要分清阶段：在孩子全部合并之前，f[u] 只代表“u 自身，以及已经合并的那些孩子”。所有孩子处理完，才得到完整的 u 子树答案。

刚开始还没合并任何孩子，只有：

```text
f[u][0] = 0          整棵不选
f[u][1] = score[u]   只选 u 自己
其余数量不可达        现在还没有别的点可以选
```

不可达用 NEG 表示，不能全填 0。比如只处理了课程 1 自己时，“恰好选 3 门”还不存在，不应以 0 分参与后面的转移。

## 第四步：逐个合并孩子

假设正在把孩子 v 的菜单合并到 u：

- i：在 u 与此前合并的孩子中，已经选了多少点。
- j：本次从 v 子树再选多少点。
- i+j：合并后总共选多少点。

两部分没有重复结点，学分可相加，因此尝试：

```text
next[i+j] = max(next[i+j], f[u][i] + f[v][j])
```

这里 i 从 **1** 开始，表示先选 u，才允许接孩子的方案；j 从 **0** 开始，表示允许不选当前孩子。next[0] 单独保留为 0，不能通过 i=0、j>0 拼出“跳过父亲直接选孩子”。

### 手算课程 1：两次合并，两张新表

课程 2、3 都是叶子，它们的菜单分别为 [0,4]、[0,7]。

| 课程 1 的计算阶段 | 选 0 点 | 选 1 点 | 选 2 点 | 选 3 点 |
| --- | --- | --- | --- | --- |
| 只有课程 1 | 0 | 3 | 不可达 | 不可达 |
| 合并课程 2 后 | 0 | 3 | 7 | 不可达 |
| 再合并课程 3 后 | 0 | 3 | 10 | 14 |

最后一行“选 2 点”有两个候选：

```text
此前选 2 点，课程 3 选 0 点：7 + 0 = 7
此前选 1 点，课程 3 选 1 点：3 + 7 = 10
取较大值 10，即选择课程 1、3
```

“选 3 点”则来自此前选 2 点、课程 3 选 1 点：7+7=14。请看到每个候选背后的选课过程，再去看代码里的 i、j。

### 手算虚拟根：名额怎样分给两棵子树

课程 4 合并课程 5 后，菜单为 [0,5,11]。0 自身占 1 个点，合并课程 1 后，f[0] 为 [0,0,3,10,14]。

接下来合并课程 4，目标是总共选 4 个点：

| 此前选 i 点（包含 0） | 从课程 4 子树选 j 点 | 候选学分 |
| --- | --- | --- |
| 1 | 3 | 课程 4 子树只有两个点，不可行 |
| 2 | 2 | 3+11=14 |
| 3 | 1 | 10+5=15 |
| 4 | 0 | 14+0=14 |

最优分配为 i=3、j=1：此前选的是 0、1、3，现在再选课程 4。去掉虚拟课程，恰好得到 1、3、4 三门真实课程。

## 用 next 保存新表，让一个孩子只合并一次

每次合并开始时新建 next，候选只从旧 f[u] 与完整的 f[v] 读取，全部算完后才令 f[u]=next。这样读到的“旧方案”一定没有包含当前孩子，保证这组方案只使用一次。

也因此，本节 j 可以从小到大枚举：新旧表分开，读取不受写入影响。前面一维 0/1 背包的倒序，是在同一数组上更新时保护上一层；理解要保护哪一层，比把“背包一定倒序”记成口诀更有用。

## 按什么顺序得到孩子的菜单

父亲合并孩子前，孩子的完整答案必须已经求出。代码先从 0 开始收集一个“父亲在孩子前面”的 order，再倒着处理，就得到“孩子在父亲前面”的计算顺序。这一顺序与结点编号大小无关。

size[u] 记录 u 与已合并部分能提供的点数，上限截到 need=m+1。它限制循环不去扫描超过实际数量的状态；数组中的 NEG 则负责排除其他不可达情况。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<int>> children(n + 1);
    vector<int> score(n + 1);
    for (int u = 1; u <= n; u++) {
        int parent;
        cin >> parent >> score[u];
        children[parent].push_back(u);
    }
    vector<int> order(1, 0);
    for (int at = 0; at <= n; at++) {
        int u = order[at];
        for (int v : children[u]) order.push_back(v);
    }
    int need = m + 1;
    const int NEG = -1000000000;
    vector<vector<int>> f(n + 1, vector<int>(need + 1, NEG));
    vector<int> size(n + 1, 1);
    for (int at = n; at >= 0; at--) {
        int u = order[at];
        f[u][0] = 0;
        f[u][1] = score[u];
        for (int v : children[u]) {
            vector<int> next(need + 1, NEG);
            next[0] = 0;
            for (int i = 1; i <= min(size[u], need); i++) {
                if (f[u][i] == NEG) continue;
                for (int j = 0; j <= min(size[v], need - i); j++) {
                    if (f[v][j] == NEG) continue;
                    next[i + j] = max(next[i + j], f[u][i] + f[v][j]);
                }
            }
            f[u] = next;
            size[u] = min(need, size[u] + size[v]);
        }
    }
    cout << f[0][need] << '\n';
    return 0;
}
```

这份实现可按 O(nm²) 估算上界，n,m≤300 时约二千七百万次候选，size 与不可达判断还会减少实际扫描。空间 O(nm)。原题真实学分总和不超过 6000，int 足够；加分之前先排除 NEG，确保只合并合法方案。

## 换一个约束时，先重新说明状态

若题目要求从根出发保留若干条边，接入孩子子树还要花一条父子边，合并数量变成 i+j+1。先决定 j 数的是点、边还是费用，再写下标，不能凭模板默认相加。

若要求覆盖每条边，即边的至少一个端点被选，则还需记录 u 选或不选：u 不选时，孩子必须选；u 选时，孩子可选可不选。如果同时限制总选择数，就将“父点状态”和“数量”一起放进状态，再按合法父子组合分配数量。

这些模型共同的步骤都是：**定义一棵子树向外提供什么信息，先解孩子，再按约束合并它们的方案。**
