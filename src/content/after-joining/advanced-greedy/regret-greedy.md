## 这一节学什么

之前的贪心常是“排好序，能选就选”。但有时后面出现了更合适的选项，过去的选择会占住资源。我们可以先选，在发生冲突时撤销一个最不划算的选择，这就是反悔贪心。

> **AI 伴学提示词**
>
> 为我讲解反悔贪心，用建筑抢修手算每次加入和撤销，解释为什么堆里删除的是耗时最长的建筑，并引导我提问。

## 先看“选了就不能改”会怎样

有四个建筑，分别需要 4、2、2、3 秒，截止时间分别为 5、6、7、8。按截止时间依次“能修就修”，会先修前两个，用掉 6 秒，后两个都赶不上，只救下两个。

但若撤销第一个，改修后三个：在时间 2、4、7 完成，可以救下三个。问题不在于排序错了，而在于我们需要有机会修改之前的选择。

这与回溯不同：不枚举所有撤销方案，而是证明发生冲突时，撤销哪一个最有利。堆只是把这个选择快速找出来。

## 例题精讲：P4053 · 建筑抢修

**原题：** [P4053 · 建筑抢修](https://www.luogu.com.cn/problem/P4053)。

**题意简述：** 一个工人依次抢修建筑。第 i 个需要 t[i] 秒，必须在 d[i] 时刻之前或恰好在该时刻修完，求最多修复多少个。n<150000，1≤t[i]<d[i]<2³¹。

下面使用符合原题范围的自拟输入：

```text
3
4 5
2 6
2 7
```

输出 `2`。按输入顺序不撤销，会在时间 4、6 修完前两个，第三个赶不上；若保留后两个，则只占用 4 秒，为后续建筑留下更多空间。

### 为什么先按截止时间排序

对已经决定修的建筑，按截止时间从早到晚安排即可。如果相邻两项中，早截止的反而在后面，把它提前：它会更早完成；晚截止的完成时间变成原来这两项的总完成时间，而这个时间本来就没有超过更早的截止时间，因此也不会超出自己的截止时间。

于是我们只需决定“保留哪些建筑”，它们的执行顺序由截止时间决定。

### 冲突时，把最长的那一个撤销

用大根堆保存已选建筑的耗时，total 表示这些建筑的总耗时。扫描到当前建筑时：

1. 先把它加入堆，total 加上它的耗时。
2. 若 total≤当前截止时间，全部保留。
3. 否则删除堆中耗时最长的一项，total 减去它。

加入前的集合已经可行。加入后只多了一个建筑，所以至少要放弃一个；删除最长的，保留数量与删除别的相同，但释放的时间最多。

可行性也要检查：若删除当前建筑，就回到旧方案；若删除旧建筑，旧建筑们的完成时间只会提前，当前建筑放在最后，新的 total 不大于加入前的 total，因为删掉的耗时至少与当前耗时一样长，所以它也能及时完成。**一次加入后，至多删除一个就够了。**

这个选择的作用贯穿后续扫描：在当前截止时间前缀里，保留最多的建筑，并在同样数量下尽量少占用时间。若某个方案删的是较短建筑，用最长建筑替换这个被删项，保留下来的总时间不会增加，后面能接上的建筑也不会变少。逐个消除这类较差选择，就得到堆中保留的方案。

### 用一组会发生反悔的数据手算

将上面的输入扩展为四个建筑：`(4,5)、(2,6)、(2,7)、(3,8)`。

| 当前建筑 | 加入后 total | 做什么 | 保留耗时与 total |
| --- | --- | --- | --- |
| (4,5) | 4 | 不超时 | {4}，4 |
| (2,6) | 6 | 恰好可行 | {4,2}，6 |
| (2,7) | 8 | 撤销耗时 4 的旧建筑 | {2,2}，4 |
| (3,8) | 7 | 加入 | {2,2,3}，7 |

第三步并没有让当前保留数量增加，但让总耗时从 6 减到 4，第四个建筑因此能加入。反悔的价值可以体现在后面的选择中。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

struct Building {
    long long time, deadline;
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    vector<Building> a(n);
    for (int i = 0; i < n; i++) cin >> a[i].time >> a[i].deadline;
    sort(a.begin(), a.end(), [](const Building &x, const Building &y) {
        return x.deadline < y.deadline;
    });
    priority_queue<long long> chosen;
    long long total = 0;
    for (const Building &current : a) {
        chosen.push(current.time);
        total += current.time;
        if (total > current.deadline) {
            total -= chosen.top();
            chosen.pop();
        }
    }
    cout << chosen.size() << '\n';
    return 0;
}
```

sort 实现“先处理早截止的”；push 实现“暂时加入”；top、pop 实现“撤销耗时最大的”。代码中的每一步，都来自前面的决策过程。

总耗时可能远超 int，即使某个单独截止时间能用 int 保存，total 仍使用 long long。排序与堆操作总时间 O(n log n)，空间 O(n)。

## 不要只记“反悔就用大根堆”

堆顶由需要撤销的对象决定。建筑抢修希望释放最多时间，所以撤销最长任务，用大根堆。若任务都是一个时间单位、目标改成总利润最大，那么冲突时应撤销利润最小的一项，要用小根堆。

先回答“资源是什么、冲突是什么、同样数量下哪种替换更优”，再决定堆里放什么、堆顶是谁。

## 练习：每次删除都说出它替换了什么

先**独立重做 P4053**，记录每一步的截止时间、堆中耗时、total。用小规模枚举所有子集，再按截止时间检查可行性，核对贪心答案。

### 推荐必做

1. [P2949 · Work Scheduling G](https://www.luogu.com.cn/problem/P2949)：任务各占一个时间单位，有截止时间和利润，最大化总利润。按截止时间扫描，用小根堆在超出可用时间时删除最小利润，练习根据目标改变反悔对象。

### 选做巩固

- [P1484 · 种树](https://www.luogu.com.cn/problem/P1484)：在直线上的坑中至多选择 k 个不相邻的位置，最大化收益。尝试把撤销中间位置、改选两侧的收益差作为新的候选，比较它与本节撤销耗时最长任务的区别。
- [P1792 · 种树](https://www.luogu.com.cn/problem/P1792)：在环上恰选 m 个互不相邻的位置，使美观度之和最大；无法选满时输出 Error!。与 P1484 对照环形相邻关系和“恰好选满”的差异。
- [P3620 · 数据备份](https://www.luogu.com.cn/problem/P3620)：将街上的办公楼配成 k 对，每栋楼至多使用一次，最小化距离之和。先分析相邻距离的选取，再考虑撤销一次选择的代价。
