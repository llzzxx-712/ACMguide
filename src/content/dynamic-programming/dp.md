## 今天要完成什么

今天学习动态规划，常简称 DP。我们会先从已经学过的递推、记忆化和搜索接过来，用最大子段和、最长上升子序列练习如何定义状态、推导转移、确定初始值和计算顺序，再通过滑雪完整练习记忆化搜索。

学习目标是：拿到题目后，能解释每个数组格子在回答什么问题，以及为什么能从之前的答案算出它。

> **AI 伴学提示词**
>
> 为我讲解动态规划，结合最大子段和、最长上升子序列和滑雪，带我定义状态、推导转移，追踪记忆化搜索的调用与复用，并引导我对可能不理解的内容进行提问。

## 你已经接触过 DP 的一些想法

第三章爬楼梯时，我们计算到每一级台阶的方案数，保存之后继续使用；计算 Function 时，发现相同参数会反复出现，就把函数结果记下来。这两种做法已经用到了动态规划的重要思想：

**把大问题拆成有联系的小问题，保存小问题的结果，避免重复计算，再用这些结果求出最终答案。**

第六章的搜索会把可选方案逐个枚举。在某些问题中，不同的枚举分支会遇到相同的小问题；如果后面的结果只由这个小问题本身决定，就可以合并这些重复工作。还有些问题，多个部分方案对未来的影响相同，只需要保留其中最优的结果。

但首先要说清“小问题是什么”。这就是**状态定义**。数组 f 只是保存答案的工具，定义写清楚了，才知道 `f[i]` 应该装什么、该怎样算。

## 写代码前，先回答五个问题

| 要回答的问题 | 会决定什么 |
| --- | --- |
| `f[i]` 或 `f[i][j]` 的准确含义是什么？ | 状态；哪些信息需要记住 |
| 这个小问题的最后一步有哪些可能？ | 转移；从哪些旧结果计算 |
| 最小的小问题可以直接得到什么答案？ | 初始值与边界 |
| 计算当前状态之前，需要先算好谁？ | 循环或递归的顺序 |
| 题目答案在表格的哪里？ | 输出一个状态，还是取若干状态的最大值 |

再数一数状态有多少个、每个要枚举多少种转移，估算时间与空间。下面的例题会反复使用这几个问题。

## 例题精讲：P1115 · 最大子段和

**原题：** [P1115 · 最大子段和](https://www.luogu.com.cn/problem/P1115)，来自[自编入门题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 给定长度为 n 的整数序列，选出连续且非空的一段，使其中元素之和最大，输出这个最大和。1≤n≤200000，−10000≤`a[i]`≤10000。

例如输入：

```text
9
-2 1 -3 4 -1 2 1 -5 4
```

输出：

```text
6
```

选择第 4 到第 7 个数，也就是 4、−1、2、1，和为 6。注意这里必须连续，不能直接把所有正数拿出来相加；也不能一个数都不选。

### 从暴力枚举想起

一段区间由左端点 l、右端点 r 决定。枚举所有区间，再逐项求和，是 $\mathcal{O}(n^{3})$。使用第三章的前缀和，每个区间可以 $\mathcal{O}(1)$ 求和，但仍有约 n²/2 个区间，整体 $\mathcal{O}(n^{2})$。

n=200000 时，这样的区间数量约为 200 亿。我们需要继续减少重复计算。

### 状态为什么要规定“恰好在 i 结束”

设 **`f[i]` 表示恰好以第 i 个数结尾的、非空连续子段的最大和**。

“以 i 结尾”这个限制很有用：既然最后一个数必须是 `a[i]`，就只需要考虑它前面怎么接。

不要一开始就把 `f[i]` 设成“前 i 个数里的最大子段和”，然后直接往它后面加 `a[i]`。例如序列 5、−100、4，前两个数里的最优段是第 1 个数 5，它与第 3 个数 4 之间隔着 −100，不能直接拼成和为 9 的连续段。

把结尾固定住，才能保证从旧状态接上当前数后，连续关系仍然成立。

### 最后一步只有两种情况

以 i 结尾的一段：

1. 只选 `a[i]`，从这里重新开始，和为 `a[i]`。
2. 长度至少为 2。去掉最后的 `a[i]`，剩下的段恰好以 i−1 结尾；其中最优和是 `f[i - 1]`，接上后得到 `f[i - 1] + a[i]`。

取两者较大值：

```text
f[i] = max(a[i], f[i - 1] + a[i])
```

为什么第二类只需要保存最大的 `f[i - 1]`？它们接下来都要加上同一个 `a[i]`。原本更小的和，加上同一个数后仍然更小，不可能反过来超过最大者。我们因此把许多以同一位置结尾的区间，合并成一个最优结果。

这也说明这里与“每步都凭直觉选一个”的区别：我们先列出当前状态所有可能的来源，再比较这些来源的最优结果。

### 用一张表，完整走过这个思路

| i | `a[i]` | 从这里重新开始 | 接上前一段 | `f[i]` | 到目前为止的最大值 ans |
| --- | --- | --- | --- | --- | --- |
| 1 | −2 | −2 | 初始位置 | −2 | −2 |
| 2 | 1 | 1 | −2+1=−1 | 1 | 1 |
| 3 | −3 | −3 | 1−3=−2 | −2 | 1 |
| 4 | 4 | 4 | −2+4=2 | 4 | 4 |
| 5 | −1 | −1 | 4−1=3 | 3 | 4 |
| 6 | 2 | 2 | 3+2=5 | 5 | 5 |
| 7 | 1 | 1 | 5+1=6 | 6 | 6 |
| 8 | −5 | −5 | 6−5=1 | 1 | 6 |
| 9 | 4 | 4 | 1+4=5 | 5 | 6 |

第 9 格的 `f[9] = 5`，但全局答案是 6。因此不能只输出 `f[n]`；题目的最优段可以在任意位置结束，要对所有 `f[i]` 取最大值。

### 初始值与计算顺序

第一个位置只能选 `a[1]`，所以 `f[1] = a[1]`，`ans = f[1]`。后面每个状态依赖前一个状态，按 i 从 2 到 n 的顺序计算。

> **题目要求非空，初始答案不能随手写成 0。**
>
> 如果输入是 −5、−2、−7，答案应为 −2，而不是 0。把 `f[1]` 与 ans 都设为 `a[1]`，就能自然处理全负数和只有一个元素的情况。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

const int N = 200000 + 5;
long long a[N], f[N];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    f[1] = a[1];
    long long ans = f[1];
    for (int i = 2; i <= n; i++) {
        f[i] = max(a[i], f[i - 1] + a[i]);
        ans = max(ans, f[i]);
    }
    cout << ans << '\n';
    return 0;
}
```

| 思路中的动作 | 代码中的实现 |
| --- | --- |
| 保存每个固定结尾的最优和 | `f[i]` |
| 比较重新开始与接上前段 | `max(a[i], f[i - 1] + a[i])` |
| 确保旧答案已经计算 | i 从小到大循环 |
| 允许最优段在任意位置结束 | 每轮更新 ans |

最大正数和为 200000×10000=2000000000，本题范围内 `int` 也能容纳；代码用 `long long` 保存和，便于之后处理更大范围的同类题。

每个位置只做常数次运算，总时间 $\mathcal{O}(n)$，保存两个数组占 $\mathcal{O}(n)$ 空间。

### 先理解完整表格，再压缩成一个变量

计算 `f[i]` 时，只用到了 `f[i - 1]`，更早的 f 都不会再访问。因此可以用 ending 保存上一个状态，更新成当前状态：

```text
ending = max(a[i], ending + a[i]);
ans = max(ans, ending);
```

如果输入也边读边处理，就不必保存 a、f 数组，额外空间能降为 $\mathcal{O}(1)$。这两行有意义，是因为我们已经知道 ending 在更新前、后分别代表哪个状态。

## 再换一种状态：最长上升子序列

前面要求连续。现在允许跳过一些元素，但保留原来的先后顺序，这叫**子序列**。

例如 3、1、2、2、5、4 中，可以选 1、2、5，它们不一定相邻，但下标递增，值也严格递增。最长长度为 3。

这里的“上升”指严格变大，相等的两个 2 不能接在一起。连续子段和、最长上升子序列是两个不同的问题，先读清题意再定义状态。

### 仍然固定最后一个位置

设 **`f[i]` 表示以 `a[i]` 结尾的严格上升子序列的最长长度**。

至少可以只选 `a[i]` 自己，所以初始 `f[i] = 1`。若前面有 j<i 且 `a[j]`<`a[i]`，就可以把 `a[i]` 接在以 `a[j]` 结尾的上升子序列后面，得到长度 `f[j] + 1`。

```text
f[i] 初始为 1
枚举所有 j < i：
    如果 a[j] < a[i]：
        f[i] = max(f[i], f[j] + 1)
```

与最大子段和相比，允许跳过元素，因此前一个被选元素可以是任何合法 j，不能只看 i−1。内层 for 正是在枚举这些可能来源。

| i | `a[i]` | 可以作为前驱的位置 | `f[i]` |
| --- | --- | --- | --- |
| 1 | 3 | 没有 | 1 |
| 2 | 1 | 没有 | 1 |
| 3 | 2 | 2 | 2 |
| 4 | 2 | 2；第 3 个数相等，不能接 | 2 |
| 5 | 5 | 1、2、3、4 | 3 |
| 6 | 4 | 1、2、3、4 | 3 |

### 自编示例：输出最长上升子序列的长度

输入 n 与 n 个整数，1≤n≤1000、数值绝对值不超过 10⁹，输出严格上升子序列的最长长度。输入上面的六个数，输出 3。

```cpp
#include<bits/stdc++.h>
using namespace std;

int a[1005], f[1005];

int main() {
    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    int ans = 1;
    for (int i = 1; i <= n; i++) {
        f[i] = 1;
        for (int j = 1; j < i; j++) {
            if (a[j] < a[i]) f[i] = max(f[i], f[j] + 1);
        }
        ans = max(ans, f[i]);
    }
    cout << ans << '\n';
    return 0;
}
```

外层枚举“当前以谁结尾”，内层枚举“上一个选了谁”，条件检查“这样接是否仍然上升”，max 负责“保留最长结果”。代码中的每个部分都对应解题流程中的一个问题。

有 n 个状态，每个最多检查 n−1 个来源，时间 $\mathcal{O}(n^{2})$、空间 $\mathcal{O}(n)$。n≤1000 时约一百万次比较；若换成 n=200000，平方级就不合适，要继续优化算法。

## 递推与记忆化：按什么顺序算小问题

本节都先算小下标，再算大下标，因为转移依赖更小下标。这叫按依赖顺序进行递推。

有时依赖关系不容易直接排成这样的下标顺序，也可以写递归：需要哪个状态，就去计算它；算出后存下来，下次直接返回。这就是**记忆化搜索**。第三章 Function 已经采用过这种写法。

下面用一道完整例题观察：递归怎样按需计算状态，记忆化又怎样跳过已经完成的工作。

## 例题精讲：P1434 · 滑雪

**原题：** [P1434 · 滑雪](https://www.luogu.com.cn/problem/P1434)，来自[自编入门题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 给定 R 行 C 列的高度图，可以从任意格子出发，每次滑到上下左右相邻、且高度严格更低的格子。求最长路线经过多少个格子。R、C≤100，高度在 0 到 10000 之间。

输入：

```text
3 3
9 8 7
2 3 6
1 4 5
```

输出：

```text
9
```

可以沿 9→8→7→6→5→4→3→2→1 滑行，经过 9 个格子。答案统计格子数，起点也算；只有一个格子时答案为 1。

### 先把暴力搜索的思路说清楚

站在 (x,y)，枚举四个相邻位置。合法且更低，就从那里继续搜索；比较每个方向的后续路线，选最长的一条，再加上当前格子。

这仍然是在枚举下一步的选择。问题在于，不同路线可能来到同一格子，之后又把相同的后续路线枚举一遍。

例如这张小图：

```text
9 7
6 2
```

从 9 可以经过 6 到 2，也可以经过 7 到 2。从 2 出发的答案不会因为之前经过了谁而改变，可以只计算一次。

### 定义一个不依赖来路的状态

设 **`f[x][y]` 表示从 (x,y) 出发的最长严格下降路线长度，包含当前格子**，`dfs(x, y)` 返回这个答案。

为什么只记坐标就够了？高度图固定，当前位置决定了接下来哪些方向合法；之前走过的格子都更高，后续严格下降也不可能回到它们。因此从这里继续能走多远，与来时路线无关。

不要把“从某个起点走到这里已经经过的长度”直接存进 `f[x][y]`。不同来路的已有长度可能不同，那就不再是同一个小问题。本节保存的是**从这里往后还能形成多长的路线**。

### 按四种下一步推导转移

先把 `f[x][y]` 设为 1，表示只停在当前格。如果相邻 (nx,ny) 在范围内，且 `a[nx][ny]`<`a[x][y]`，就能接上从它出发的最优路线：

```text
f[x][y] = max(f[x][y], 1 + dfs(nx, ny))
```

四个方向都比较完，当前状态就算完了。若没有更低的邻居，答案自然保持 1，不必另外写一个“谷底”的特殊判断。

### 跟着调用与返回，观察答案怎样复用

仍看上面的 2×2 小图，假设先尝试向下，再尝试向右：

```text
dfs(1,1)：高度 9
    dfs(2,1)：高度 6
        dfs(2,2)：高度 2，没有更低邻居，保存 1，返回
        保存 f[2][1] = 1 + 1 = 2，返回
    dfs(1,2)：高度 7
        dfs(2,2)：发现 f[2][2] 已经算过，直接返回 1
        保存 f[1][2] = 1 + 1 = 2，返回
    保存 f[1][1] = 1 + max(2,2) = 3，返回
```

第一次到达 2，函数负责计算并保存；第二次到达 2，函数立刻返回已有结果，四个方向的循环不再执行。最终的表是：

```text
高度 a：      路线长度 f：
9 7           3 2
6 2           2 1
```

高度与长度是不同的量。例如地图只有一个高度为 10000 的格子，路线长度仍然只有 1。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int R, C;
int a[105][105], f[105][105];
int dx[4] = {-1, 1, 0, 0};
int dy[4] = {0, 0, -1, 1};

int dfs(int x, int y) {
    if (f[x][y] != 0) return f[x][y];

    f[x][y] = 1;
    for (int k = 0; k < 4; k++) {
        int nx = x + dx[k];
        int ny = y + dy[k];
        if (nx < 1 || nx > R || ny < 1 || ny > C) continue;
        if (a[nx][ny] >= a[x][y]) continue;
        f[x][y] = max(f[x][y], 1 + dfs(nx, ny));
    }
    return f[x][y];
}

int main() {
    cin >> R >> C;
    for (int i = 1; i <= R; i++) {
        for (int j = 1; j <= C; j++) cin >> a[i][j];
    }

    int ans = 0;
    for (int i = 1; i <= R; i++) {
        for (int j = 1; j <= C; j++) {
            ans = max(ans, dfs(i, j));
        }
    }
    cout << ans << '\n';
    return 0;
}
```

| 解题思路 | 对应代码 |
| --- | --- |
| 相同小问题只算一次 | 函数开头检查 `f[x][y]` 是否非 0 |
| 只停在自己也有一个格子 | `f[x][y] = 1` |
| 枚举下一步的四种选择 | 方向数组与 for |
| 先保证数组合法，再检查高度 | 两个 continue |
| 接上下一格的最优后续 | 1+`dfs(nx, ny)` |
| 起点可以是任意位置 | main 中枚举所有起点取最大值 |

全局 f 初始为 0；每个合法状态的答案至少为 1，因此 0 可以明确表示“还没计算”。即使高度本身为 0，也不影响这个标记，因为高度保存在另一个数组 a 中。

### 为什么不需要回溯撤销，也不会无限递归

每次调用都去更低的格子，高度严格下降，不可能绕一圈回到原位置，也不会再次进入一个尚未返回的祖先调用。等一个格子的递归结束，它的答案已经完整，之后访问时就可以复用。

第六章枚举某条路径时，有些标记只对当前方案有效，返回时要恢复；这里保存的是固定地图上“从这个位置出发”的完整答案，返回时不能清空。若清空，下一条来路又会把它重算一次。

### 时间、空间与递归顺序

每个格子的四方向循环只完整执行一次，后来调用直接返回，时间 $\mathcal{O}(RC)$。答案数组占 $\mathcal{O}(RC)$，递归调用栈最深也不超过 RC 个格子。

虽然 main 按行列枚举起点，**真正的计算顺序由依赖决定**：更高格子需要更低格子的答案时，会先递归把后者算好，再返回。也可以把格子按高度从低到高排序，用循环完成同样的依赖关系。
