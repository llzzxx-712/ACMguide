## 二维状态：每个坐标回答一个小问题

上一节 f[i] 的下标表示结尾位置。现在可以用 f[i][j] 表示某个二维位置的答案，但数组多一维并不是目的：我们需要这两个下标准确描述当前的小问题。

数字三角形中，行号、列号决定接下来能走到哪里；背包中，已经考虑的物品数量、允许使用的容量决定剩下有哪些选择。下标保存什么，来自题目中的解题思路。

## 例题精讲：P1216 · 数字三角形

**原题：** [P1216 · 数字三角形](https://www.luogu.com.cn/problem/P1216)，来自[自编入门题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 从数字三角形顶端出发，每次走到左下或右下，直到最底层，求经过数字之和的最大值。行数 n≤1000，每个数字在 0 到 100 之间。

我们用下面这组输入说明：

```text
4
5
9 1
1 1 20
1 1 1 1
```

输出：

```text
27
```

从顶端出发，每次选眼前较大的数，会先走到 9，之后到不了右侧的 20。正确路线是 5→1→20→1，总和为 27。我们需要比较的是两条后续路线的总收益。

### 从暴力搜索发现重复的小问题

在非底层的每个位置，都可以向两个方向试。直接 DFS 枚举完整路线，最多有 2ⁿ⁻¹ 条，n=1000 时无法逐条检查。

但不同路线可能走到同一位置。例如第三行第二个数，既能从第二行第一列来，也能从第二行第二列来。**从这个位置往下的最优路线，只与当前位置有关，与之前怎么走到这里无关。**

因此可以把“从这个位置到底层最多能得到多少”单独算好，让所有来到这里的路线共用。

### 状态与转移

设 **f[i][j] 表示从第 i 行第 j 列出发，一直走到底层的最大路径和，包含当前格子**。

下一步只有两个选择：

```text
当前位置 (i,j)
     /       \
(i+1,j)   (i+1,j+1)
```

无论选哪条，都先得到 a[i][j]。之后取两种后续结果中较大的：

```text
f[i][j] = a[i][j] + max(f[i + 1][j], f[i + 1][j + 1])
```

底层没有下一步，直接 f[n][j]=a[n][j]。当前行依赖下一行，所以**从下往上算**。

### 手填整张表

```text
原数字：                         从这里到底层的最优和：
          5                                 27
        9   1                             11  22
      1   1   20                         2   2  21
    1   1   1   1                       1   1   1   1
```

例如 f[2][2]=1+max(2,21)=22，再算 f[1][1]=5+max(11,22)=27。输出顶端的这个状态，就回答了整道题。

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int a[1005][1005], f[1005][1005];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= i; j++) cin >> a[i][j];
    }

    for (int j = 1; j <= n; j++) f[n][j] = a[n][j];
    for (int i = n - 1; i >= 1; i--) {
        for (int j = 1; j <= i; j++) {
            f[i][j] = a[i][j] + max(f[i + 1][j], f[i + 1][j + 1]);
        }
    }
    cout << f[1][1] << '\n';
    return 0;
}
```

| 思路 | 代码 |
| --- | --- |
| 三角形每行只有 i 个格子 | 内层 j 从 1 到 i |
| 底层的路线只包含自己 | 单独初始化 f[n][j] |
| 比较左下与右下的完整收益 | max(f[i+1][j], f[i+1][j+1]) |
| 先算依赖，再算当前位置 | 外层 i 递减 |
| 从顶端出发 | 输出 f[1][1] |

状态约 n(n+1)/2 个，每个只比较两个来源，时间 O(n²)、空间 O(n²)。最大路径和为 1000×100=100000，int 足够。

### 改成矩形网格时，重新确定依赖

若在矩形里只能向右、向下走，设 f[i][j] 为“从左上角到 (i,j) 的最大收益”，那么最后一步只能来自上方或左方：

```text
f[i][j] = max(f[i - 1][j], f[i][j - 1]) + a[i][j]
```

这次要从上往下、从左往右算。起点、第一行、第一列需要单独考虑；若有障碍，要区分不可达状态。求方案数时则把合法来源的方案数相加。

**先写状态含义与移动规则，再决定从哪边转移、按什么顺序循环。** 只记住一个二维公式，很容易把“从这里出发”与“到达这里”混用。

## 例题精讲：P1048 · 采药

**原题：** [P1048 · 采药](https://www.luogu.com.cn/problem/P1048)，来自[自编入门题单](https://www.luogu.com.cn/training/1126196)。

**题意简述：** 共有 m 株草药，每株有采摘耗时 w[i] 和价值 v[i]，每株最多采一次。总时间不超过 T，求最大总价值。T≤1000、m≤100，每株耗时、价值都在 1 到 100 之间。

这里的“背包”是一个比喻：时间 T 就像容量，每株草药的耗时占用容量，价值是想最大化的收益。这类每件物品最多选一次的问题，叫 **0/1 背包**，对应“选 0 次或 1 次”。

### 先比较所有可能的选择

每株草药都有采与不采两个分支，直接 DFS 最多检查 2ᵐ 种选法。背包 DP 会把“考虑到第几株、还允许用多少总时间”相同的部分问题合并。

不能简单地每次选价值最高、耗时最少或单位时间价值最高的草药。比如 T=4，有一株耗时 3、价值 5，还有两株各耗时 2、价值 3。先选单位时间价值最高的第一株只能得到 5；选后两株得到 6。

### 状态中要同时保存两种信息

设 **f[i][j] 表示只考虑前 i 株草药，总耗时不超过 j 时，能取得的最大总价值**。

- i 决定当前哪些草药可以选。
- j 决定允许用多少时间。
- f[i][j] 存的是最大价值，不是已经用掉的时间。

这里 j 是上限，不要求恰好用满。例如只有耗时 3、价值 5 的一株药，f[1][4] 也是 5。

### 按“第 i 株选不选”分类

1. 不采第 i 株：只用前 i−1 株，时间上限仍为 j，答案为 f[i−1][j]。
2. 采第 i 株：必须 j≥w[i]。先为它留出 w[i] 时间，前 i−1 株最多用 j−w[i]，价值为 f[i−1][j−w[i]]+v[i]。

因此：

```text
f[i][j] = f[i - 1][j]
如果 j >= w[i]：
    f[i][j] = max(f[i][j], f[i - 1][j - w[i]] + v[i])
```

两种情况都从第 i−1 行读取，保证第 i 株只用一次。每个合法选法必然属于其中一类，所以两类比较就覆盖了所有可能。

### 手填一张小背包表

输入：

```text
4 3
3 5
2 3
2 3
```

输出：

```text
6
```

表格的列是时间上限 j：

| 已考虑的草药 | j=0 | j=1 | j=2 | j=3 | j=4 |
| --- | --- | --- | --- | --- | --- |
| 0 株 | 0 | 0 | 0 | 0 | 0 |
| 第 1 株：耗时 3、价值 5 | 0 | 0 | 0 | 5 | 5 |
| 再考虑第 2 株：耗时 2、价值 3 | 0 | 0 | 3 | 5 | 5 |
| 再考虑第 3 株：耗时 2、价值 3 | 0 | 0 | 3 | 5 | 6 |

右下角比较“不采第 3 株的 5”和“前两株在时间上限 2 时的 3，再加本株价值 3”，得到 6。第 2、3 株即使耗时、价值相同，也确实是两株不同的药，可以各选一次。

### 初始化与答案

没有考虑任何草药时，最多取得 0 价值，所以 f[0][j]=0。时间上限为 0 时也只能不采，f[i][0]=0。

允许不选，且容量表示“至多使用”，全表先为 0 是正确的。答案是 f[m][T]，不必要求恰好用满 T。

### 二维完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int w[105], v[105];
int f[105][1005];

int main() {
    int T, m;
    cin >> T >> m;
    for (int i = 1; i <= m; i++) cin >> w[i] >> v[i];

    for (int i = 1; i <= m; i++) {
        for (int j = 0; j <= T; j++) {
            f[i][j] = f[i - 1][j];
            if (j >= w[i]) {
                f[i][j] = max(f[i][j], f[i - 1][j - w[i]] + v[i]);
            }
        }
    }
    cout << f[m][T] << '\n';
    return 0;
}
```

数组定义在全局，自动初始化为 0。时间 O(mT)，空间 O(mT)。本题最多约十万次状态更新、总价值最多 10000，int 足够。

注意二维代码中的 j 从小到大完全正确，因为每次读取的都是上一行；循环方向的问题出现在下面的**同一数组覆盖更新**中。

## 一维优化：保留上一行需要的数据

计算第 i 行时只依赖第 i−1 行，因此可以省去物品维度，用 f[j] 覆盖保存结果。

但覆盖有顺序：更新当前物品之前，f[j] 表示“前 i−1 株、时间至多 j”的最优值；更新后表示“前 i 株、时间至多 j”的最优值。

```text
f[j] = max(f[j], f[j - w[i]] + v[i]);
```

这行公式读取的 f[j−w[i]]，必须仍然属于上一行，才能保证当前物品最多用一次。

### 为什么要从大容量向小容量更新

只有一株耗时 2、价值 3 的药，T=4，初始所有 f 都是 0。

若从小到大更新：

```text
j=2：f[2] = 3
j=4：读取刚更新的 f[2]，得到 f[4] = 6
```

同一株被采了两次，违反题意。

若从大到小更新：

```text
j=4：读取尚未更新的 f[2]=0，得到 f[4]=3
j=3：读取尚未更新的 f[1]=0，得到 f[3]=3
j=2：读取 f[0]=0，得到 f[2]=3
```

因为 j−w[i] 小于 j，倒序时它还没被本轮改写，读到的就是上一行。**倒序是在保护状态所属的物品阶段。**

> **0/1 背包一维优化：物品在外层，容量从大到小。**
>
> 不要只背“倒序”两个字。先指出转移需要上一行的哪个格子，再解释为什么此时它仍然没有被覆盖。

### 一维完整代码

下面这份程序也可以直接提交 P1048。先确认自己能解释二维代码，再对照删除了什么信息。

```cpp
#include<bits/stdc++.h>
using namespace std;

int f[1005];

int main() {
    int T, m;
    cin >> T >> m;
    for (int i = 1; i <= m; i++) {
        int w, v;
        cin >> w >> v;
        for (int j = T; j >= w; j--) {
            f[j] = max(f[j], f[j - w] + v);
        }
    }
    cout << f[T] << '\n';
    return 0;
}
```

时间仍是 O(mT)，额外空间降为 O(T)。每读入一株草药，就完成它对应的一整行更新，因此也不必保存所有草药。

## 允许同一种物品选多次，会发生什么

如果每种草药可以无限次采摘，就变成**完全背包**。此时“已经采过当前种类”的结果还能继续使用，转移可以从当前行读取：

```text
不选这一种：f[i - 1][j]
至少选一次：f[i][j - w[i]] + v[i]
```

第二项中的行号是 i，不是 i−1。先给当前种类再留一份耗时，剩下的容量里仍然可以包含这个种类。

对应一维代码就是让容量从小到大：

```text
for (int i = 1; i <= m; i++) {
    for (int j = w[i]; j <= T; j++) {
        f[j] = max(f[j], f[j - w[i]] + v[i]);
    }
}
```

刚才一株耗时 2、价值 3，在容量 4 时得到 6，此时恰好是允许的答案。正序让“已经使用当前物品的结果”继续参与转移。

| 模型 | 当前物品能选几次 | 一维容量顺序 | 转移读取的阶段 |
| --- | --- | --- | --- |
| 0/1 背包 | 至多一次 | 大到小 | 前 i−1 件 |
| 完全背包 | 可以重复 | 小到大 | 可以包含第 i 种 |

顺序来自选择次数和状态依赖。换一个问题，先重新确认含义，再决定是否适用这两行循环。

## “恰好装满”和“至多容量”要分别初始化

采药允许留下空闲时间，因此每个时间上限都可以先选空集，初始为 0。

如果题目改成“恰好花掉 j 时间的最大价值”，那么初始时只有 f[0]=0，其他正时间还不可达，不能也赋成 0，否则程序会误以为这些时间已经有合法选法。

对最大值问题，可以用足够小的负数表示不可达，并只从可达状态转移。若改为统计恰好装满的方案数，则 f[0]=1 表示空选法，其他格子初始为 0，转移改成累加方案数。

这里的初始化与上一节最大子段和不能随手设 0 是同一个要求：**先确定这个格子代表什么，再给它一个符合含义的初始答案。**

## 练习：先重做，再改变容量和选取次数

独立完成 [P1216 · 数字三角形](https://www.luogu.com.cn/problem/P1216) 与 [P1048 · 采药](https://www.luogu.com.cn/problem/P1048)。采药先写二维，再写一维，对照同一组小数据。测试一株药、所有药都采不起、恰好装满、最优解留有空余、两株属性相同的药。

### 推荐必做

1. [P1049 · 装箱问题](https://www.luogu.com.cn/problem/P1049)：每件物品只能放一次，要求剩余体积最小。把体积同时当作耗费与价值，先求不超过容量 V 的最大已用体积，最后输出 V−f[V]；注意题目输入顺序是容量、物品数。
2. [P2722 · 总分](https://www.luogu.com.cn/problem/P2722)：每类题目可以重复做，时间内求最大分数，是完全背包。输入每类是“分数、耗时”，与采药的“耗时、价值”顺序相反；容量正序更新。n、总时间 m 都可达 10000，O(nm) 最多约 10⁸ 次更新，结合第二章的常数概念估算。

### 选做：需要继续巩固时练习

1. [P1164 · 小 A 点菜](https://www.luogu.com.cn/problem/P1164)：每道菜只有一份，统计恰好花完预算的选法数。用 f[0]=1、其他为 0，容量倒序，把 max 改为累加；相同价格的不同菜也属于不同选择。
2. [P1616 · 疯狂的采药](https://www.luogu.com.cn/problem/P1616)：每种药可无限采，练习完全背包与大范围数据。容量可达 10⁷，题目保证“种类数×容量”不超过 10⁷；价值和使用 long long，一维数组开在全局，按实际容量检查空间。

对应题单：[自编入门题单](https://www.luogu.com.cn/training/1126196)。
