## 判断的对象：轮到当前玩家的局面

有一堆石子，两人轮流取，每次至少取 1 个、最多取 3 个，不能超过剩余数量。轮到谁时已经没有石子可取，谁就输，也就是取走最后一个的人赢。

先看剩余石子数 n 很小时，会发生什么：

| 剩余 n | 当前玩家可以怎么做 | 结论 |
| --- | --- | --- |
| 0 | 无法操作 | 必败 |
| 1 | 取走 1 个，让对手面对 0 | 必胜 |
| 2 | 取走 2 个，让对手面对 0 | 必胜 |
| 3 | 取走 3 个，让对手面对 0 | 必胜 |
| 4 | 只能让对手面对 3、2、1，对手都能取完 | 必败 |
| 5 | 取 1 个，让对手面对 4 | 必胜 |
| 6 | 取 2 个，让对手面对 4 | 必胜 |
| 7 | 取 3 个，让对手面对 4 | 必胜 |
| 8 | 只能让对手面对 7、6、5 | 必败 |

**必胜态**表示当前玩家存在一种策略，无论对手怎样应对，都能获胜。**必败态**表示对手正确应对时，当前玩家无论怎样操作都会输。

这里默认双方都尽力选择对自己最有利的操作。必胜不是随便取都能赢；n=5 时取 1 个能赢，取 2 个却会把 n=3 交给对手，让对手直接取完。

### “当前玩家”会随着操作改变

从 n=5 取走 1 个之后，n=4 是**对手轮到操作的局面**。所以“存在一种操作能走到必败态”意味着当前玩家能赢：这个必败态是交给对手的。

因此状态不能始终理解成“最开始那位玩家是否获胜”。我们在每个局面里，都站在即将操作的那个人的角度判断。

## 从思路得到两条判断规则

对本章这种双方可选操作相同、信息公开、一定会结束且无法操作者输的游戏：

1. **只要存在一种合法操作，能到达必败态，当前就是必胜态。** 选这一步，把难题交给对手。
2. **如果所有合法操作都到达必胜态，当前就是必败态。** 无论怎么选，都会给对手留下必胜策略。

没有合法操作时，直接按规则判负。石子只会减少，因此可以从小局面推到大局面，不会出现一直绕圈的情况。

```text
当前局面
├─ 操作 A → 对手必胜
├─ 操作 B → 对手必败  ← 只要找到这样的一个操作，当前就必胜
└─ 操作 C → 对手必胜
```

如果三个后继全部是对手必胜，当前才判必败。理解“存在一个”和“所有”的区别，比先记一个取余公式更重要。

## 例题精讲：AtCoder DP K · Stones

**原题：** [AtCoder DP K · Stones](https://atcoder.jp/contests/dp/tasks/dp_k)。

**题意简述：** 有 K 个石子，允许每次取走的数量在给定的 N 个正整数中，两人轮流操作，无法操作者输。判断先手是否获胜，输出 First 或 Second。N≤100、K≤100000，允许的数量按严格递增顺序给出，且不超过 K。

这次允许的数量可能是 2、3，不一定是连续的 1 到某个上限，因此先按合法操作逐个推导状态。

输入：

```text
2 4
2 3
```

输出：

```text
First
```

先手取 3 个，剩下 1 个。对手虽然还有石子，但允许的取法只有 2、3，已经无法操作，所以输。**无法操作，不一定意味着石子恰好为 0。**

### 状态、初始值与转移

设 **win[x] 表示剩下 x 个石子、轮到当前玩家操作时，是否为必胜态**。

- win[0]=false：没有石子，无法操作。
- 对 x>0，先假定为 false，再枚举允许的数量 take。
- 若 take≤x 且 win[x−take] 为 false，说明可以把对手送进必败态，令 win[x]=true。
- 找到一个这样的操作就够了，可以 break；如果没有找到，保留 false。

```text
win[x] = false
枚举每种允许的取法 take：
    如果 take <= x，并且 win[x - take] 为 false：
        win[x] = true
        结束当前枚举
```

每个后继的石子数都更小，所以 x 从 1 递增到 K。与背包相比，这里保存的是能否获胜，而不是最大价值；不要看到数组和两层 for 就直接套 max。

### 手算允许取 2 或 3 个的情况

| x | 合法后继 | win[x] | 理由 |
| --- | --- | --- | --- |
| 0 | 无 | false | 无法操作 |
| 1 | 无 | false | 数量不足，仍无法操作 |
| 2 | 0 | true | 可以到达必败态 0 |
| 3 | 1、0 | true | 可以到达必败态 |
| 4 | 2、1 | true | 取 3 个，留下必败态 1 |
| 5 | 3、2 | false | 两个后继都是必胜态 |
| 6 | 4、3 | false | 两个后继都是必胜态 |
| 7 | 5、4 | true | 取 2 个，留下必败态 5 |

### 完整代码

```cpp
#include<bits/stdc++.h>
using namespace std;

int a[105];
bool win[100000 + 5];

int main() {
    int N, K;
    cin >> N >> K;
    for (int i = 1; i <= N; i++) cin >> a[i];

    for (int x = 1; x <= K; x++) {
        win[x] = false;
        for (int i = 1; i <= N; i++) {
            int take = a[i];
            if (take <= x && !win[x - take]) {
                win[x] = true;
                break;
            }
        }
    }
    if (win[K]) cout << "First\n";
    else cout << "Second\n";
    return 0;
}
```

全局 bool 数组初始为 false。`!win[x-take]` 表示“这个后继是必败态”；先判断 take≤x，再访问数组，避免下标为负数。

外层循环安排计算顺序，内层循环枚举当前的所有选择，if 检查是否能把对手送进必败态，break 对应“找到一个获胜选择就足够”。这就是自然语言判断规则的逐步实现。

状态有 K+1 个，每个最多检查 N 种操作，时间 O(NK)、空间 O(K+N)。最大约一千万次操作检查。

## 巴什博弈：每次可以取 1 到 m 个

回到开头的连续取法，把上限 3 换成 m，其他规则不变。这类一堆石子、每次取 1 到 m 个、无法操作者输的游戏，通常叫巴什博弈。

从小规模表格观察，m=3 时，0、4、8、12……是必败态。可以猜测：**n 是 m+1 的倍数时必败，否则必胜。** 接下来要说明为什么。

### 从倍数局面出发，一定离开倍数

若 n 是 m+1 的倍数，当前只能取 1 到 m 个，无法取走整整 m+1 个。因此操作后剩下的数量一定不是 m+1 的倍数。

### 从非倍数局面出发，一定能回到倍数

若余数 r=n%(m+1) 不为 0，r 必在 1 到 m 之间。取走 r 个，就能留下 m+1 的倍数。

结合 0 是必败态，从小到大推导：

```text
倍数局面：所有操作都去非倍数局面 → 必败
非倍数局面：有一步可以去倍数局面 → 必胜
```

这两条性质正好与前面的必败、必胜定义相对应，所以规律对所有 n 成立。

### 怎样把必胜策略执行下去

例如 n=10、m=3，先取 2 个，留 8 个。之后对手取 k 个，你就取 4−k 个，让两人的这一轮合计取 4 个，把对手再次送回 4 的倍数。最终你取走最后一批，留 0 给对手。

对手每次只能取 1、2、3，所以回应的 4−k 也在 1、2、3 中，是合法操作。

### 自编示例：输出一堆石子的胜负

输入 n、m，0≤n≤10¹⁸、1≤m≤10⁹，规则为每次取 1 到 m 个，无法操作者输。先手有必胜策略输出 First，否则输出 Second。

例如输入 `10 3`，输出 `First`；输入 `8 3`，输出 `Second`。

```cpp
#include<bits/stdc++.h>
using namespace std;

int main() {
    long long n, m;
    cin >> n >> m;
    if (n % (m + 1) != 0) cout << "First\n";
    else cout << "Second\n";
    return 0;
}
```

时间、空间都是 O(1)。这段代码很短，因为前面的推导已经把所有局面归纳成了一个取余判断。**短代码是思路推导的结果。**

若题目改为取走最后一个的人输，0 的含义和后续结论都会变化；若允许的取法不是连续的 1 到 m，也要重新按操作分析。

## 例题精讲：P2197 · Nim 游戏

**原题：** [P2197 · Nim 游戏](https://www.luogu.com.cn/problem/P2197)。

**题意简述：** 有 n 堆石子，每次必须选一堆，取走其中至少 1 个，可以整堆取完；不能跨堆，也不能不取。无法操作者输，判断先手有无必胜策略。题目有 T 组数据，T≤10、n≤10000，每堆数量在 0 到 2³¹−1 之间，输出 Yes 或 No。

输入：

```text
3
3
1 2 3
3
3 4 5
2
0 0
```

输出：

```text
No
Yes
No
```

### 先从两堆相同的石子理解“回应”

两堆都是 2 时，先手不管在一堆取几个，后手都在另一堆取同样多个，让两堆再次相同。后手总能回应，最终把两堆都取空，先手无法再操作。

这个对称策略帮助我们理解必败局面，但堆数变多后，不能只检查是否两两相同。例如 (1,2,3) 也是必败态，需要用一个能描述所有堆关系的量。

### 用第七章的异或合并数量

设 s=a[1]^a[2]^…^a[n]，也叫所有堆的异或和。Nim 的结论是：

- s=0：当前玩家处于必败态。
- s≠0：当前玩家处于必胜态。

先回忆 `^` 是二进制逐位异或，相同位得 0，不同位得 1；a^a=0，a^0=a，调整先后顺序不影响结果。

```text
1：001
2：010
3：011
异或：000 → 必败

3：011
4：100
5：101
异或：010 → 必胜
```

结论仍然要用“必败态只能走向必胜态、必胜态能走向必败态”来说明。

### 性质一：异或和为 0，操作后一定不为 0

一次操作只把某一堆的 a 减少为 b，b<a。新异或和就是：

```text
新 s = 旧 s ^ a ^ b
```

异或 a 会把原来的那份 a 抵消，再异或 b 就换成新数量。若旧 s=0，新 s=a^b；a 与 b 不同，所以至少一个二进制位不同，结果一定非 0。

因此从异或和为 0 的局面，任何一步都会离开这类局面。

### 性质二：异或和非 0，一定能操作到 0

找 s 的最高一个 1 所在的二进制位。所有堆在这一位的 1 有奇数个，因此至少能找到一堆 a，在这一位是 1。

令新数量 b=a^s。在更高位，s 全是 0，a 不变；在刚找到的这一位，a 从 1 变成 0。因此 b<a，可以合法地从这堆中取走 a−b 个。

操作后：

```text
新 s = s ^ a ^ b
     = s ^ a ^ (a ^ s)
     = 0
```

例如 (3,4,5) 的 s=2，选择第一堆，把 3 变成 3^2=1，取走 2 个，留下 (1,4,5)，异或和变为 0。

全空局面异或和为 0，按规则为必败；每次操作都减少石子，游戏一定结束。上面两条性质就确定了所有局面的胜负。

### 完整代码

题目只要求判断胜负，所以不需要真的模拟整局，也不需要在代码中找出具体取哪一堆。将所有数量异或起来即可。

```cpp
#include<bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;
    while (T--) {
        int n;
        cin >> n;
        int s = 0;
        for (int i = 1; i <= n; i++) {
            int a;
            cin >> a;
            s ^= a;
        }
        if (s != 0) cout << "Yes\n";
        else cout << "No\n";
    }
    return 0;
}
```

`s ^= a` 等价于 `s = s ^ a`。每组都要重新把 s 设为 0，避免上一组影响下一组。输入数量都在非负 int 范围内，异或也只涉及这些有效位，int 足够。

每组时间 O(n)，额外空间 O(1)。这里没有把每堆存入数组，因为判断只需要逐个合并后的异或和。

## 把思路与实现再对照一次

| 游戏规则 | 怎样分析 | 怎样实现 |
| --- | --- | --- |
| 给出可取数量列表 | 枚举合法后继，找有没有必败态 | win 数组与两层循环 |
| 一堆，每次取 1 到 m 个 | 证明 m+1 的倍数是必败态 | n%(m+1) |
| 多堆，每次从一堆任取正数 | 证明异或和为 0 是必败态 | 逐个异或 |

拿到题目先确认局面怎样变化、谁无法操作、最后一手怎样判胜，再判断能否使用已经证明过的规律。

如果暂时找不到规律，就先对小规模局面枚举后继、画出胜负表。观察得到猜想，再证明所有可能的操作都符合它。搜索、DP、数学推导在这里是连在一起的。
