## 今天要完成什么

第一章学会了读入数据、判断、循环和数组。今天把这些工具组合起来：从题目中找出要记录的信息，按规则一步步更新，再估算程序需要做多少次操作。

> **AI 伴学提示词**
>
> 为我讲解模拟，先带我手算、说清解题思路，再把每一步对应到变量、判断和循环；讲解复杂度估算与 `cin` 关闭流同步，并引导我对可能不理解的内容进行提问。

## 先建立一个贯穿算法竞赛的观念：代码是思路的实现

拿到一道题，先问自己：“我准备怎样得到答案？”再问：“我怎么用代码把这个过程实现出来？”

**代码是思路的实现。** 变量用来保存思考中需要记住的信息，判断用来处理不同情况，循环用来重复某些步骤，函数用来组织一件相对独立的事情。先把这些事情想清楚，代码里的每一部分就都有了来由。

例如后面要做的“统计连续升温的最长天数”，我们先用纸笔比较每天的气温，发现升温就延长当前这一段，否则从今天重新算一段，同时记住见过的最长长度。想清楚这个过程之后，才决定用 $\mathrm{previous}$、$\mathrm{length}$、$\mathrm{best}$ 保存哪些信息。

学习例题时，也按这个顺序来：

1. **先把题意说给自己听。** 输入什么，要求什么，哪些条件必须满足？
2. **用一组小数据手算。** 一边算，一边记录自己每一步做了什么、需要记住什么。
3. **整理成能反复执行的规则。** 换一组数值，这个过程是否仍然成立？
4. **为这些步骤选择代码工具。** 用哪个变量保存信息，用哪个判断区分情况，用哪个循环重复处理？
5. **让代码与手算走同一遍。** 检查每一步的状态是否相同，再用边界情况验证。

如果一段代码看不懂，先回到它要实现的那一步：这行是在记录信息、检验条件，还是推进处理？如果想写代码却不知道从哪里下手，先把解题过程写成中文步骤，再逐条实现。

> **学例题，要能从思路重新写出代码。**
>
> 关掉代码后，先复述“我要保存哪些信息、按什么顺序处理、什么时候更新答案”，再独立实现。变量名和具体写法可以不同，只要它们正确地完成了同一个解题过程。
>
> 后面学习排序、递推、二分和搜索时，也一直沿用这个顺序。

## 模拟：把题目的过程交给程序执行

假设账户原来有 10 元，接下来收到 5 元、花掉 3 元、再收到 2 元。我们会依次计算：

| 操作 | 操作前的余额 | 操作后的余额 |
| --- | --- | --- |
| 收到 5 元 | 10 | 15 |
| 花掉 3 元 | 15 | 12 |
| 收到 2 元 | 12 | 14 |

程序只要用 balance 保存当前余额，每次执行 `balance += change;`，就能按同样的过程计算。这就是模拟：**把规则变成明确的操作，按照要求的顺序执行。**

余额是这个过程的**状态**，也就是“进行到这里时，需要记住的信息”。不同题目的状态可能是位置、比分、方向、剩余数量，也可能是一组数组元素。

## 读题时先整理四件事

1. **初始状态是什么？** 余额从多少开始？位置从哪里开始？第一天已经知道什么？
2. **每次操作怎样改变状态？** 增加、减少、移动，还是重新开始计数？
3. **什么时候结束或重置？** 读完 $n$ 次操作、遇到结束标记，还是一局比赛结束？
4. **最终输出什么？** 当前状态、过程中的最大值，还是全部过程？

写代码之前，先用一组小数据手算，把状态变化列成表。这样代码里的每个变量都有具体含义，每次赋值也都有理由。

以余额为例，“记住现在有多少钱”对应变量 balance，“处理每一笔收支”对应循环，“把本次变化加进去”对应 balance+=change。我们是先有这套处理规则，再选择相应写法。

## 同样能算出答案，计算量可能差很多

假设有 $n$ 个数：

- 从头到尾看一遍，需要处理 $n$ 次数据。
- 每个数都与全部 $n$ 个数比较，要做大约 $n^2$ 次比较。
- 固定执行 10 次操作，次数不会随着 $n$ 增长。

**计算复杂度，是为了判断自己的程序能否通过本题。** 题目会给出数据范围和时间限制。写代码前，把最大规模代入自己的算法，估算需要执行多少次操作，就能判断应该直接实现，还是先想一个计算量更小的方案。

### 用大 $O$ 表示增长速度

**时间复杂度**描述数据规模增大时，主要计算量怎样增长。先记住下面几种常见情况：

| 写法或过程 | 主要计算量 | 时间复杂度 |
| --- | --- | --- |
| 只做固定次数的计算 | 不随 $n$ 增长 | $\mathcal{O}(1)$ |
| 一个循环遍历 $n$ 个数 | 约 $n$ 次 | $\mathcal{O}(n)$ |
| 两层循环，各执行 $n$ 次 | 约 $n^2$ 次 | $\mathcal{O}(n^{2})$ |
| 两层循环，分别执行 $n$、$m$ 次 | 约 $n\times m$ 次 | $\mathcal{O}(nm)$ |
| 用 `sort` 排 $n$ 个数 | 按 $n\log n$ 的量级增长 | $\mathcal{O}(n \log n)$ |

大 $O$ 主要看增长最快的部分。例如先遍历一遍，再遍历一遍，总共约 $2n$ 次，仍记为 $\mathcal{O}(n)$；先做 $n$ 次，再做 $n^2$ 次，整体记为 $\mathcal{O}(n^{2})$。

$\log_2 n$ 可以先理解成“一个数反复减半，直到 1，大约能减几次”。例如 1024 减半 10 次得到 1；$n=100000$ 时，$\log_2 n$ 约为 17。复杂度中的 $\log$ 通常省略底数。

| $n$ | 一遍扫描：$n$ | 两层全遍历：$n^2$ | $n\log_2 n$，约 |
| --- | --- | --- | --- |
| 1000 | 1000 | 1000000 | 10000 |
| 100000 | 100000 | 10000000000 | 1700000 |

从这里能看到：当 $n$ 达到十万，$\mathcal{O}(n^{2})$ 与 $\mathcal{O}(n \log n)$ 的计算量已经相差很大。后面学习排序、枚举优化时，我们会继续用这种方法判断方案是否合适。

### 把最大 $N$ 代入，与 $10^8$ 比较

大部分入门题的时限是 1 秒。做题时常用下面的方式估算：

1. 算出时间复杂度，例如 $\mathcal{O}(n^{2})$ 或 $\mathcal{O}(n \log  n)$。
2. 把题目允许的**最大 $N$** 代入。
3. 结果小于 **$10^8$，也就是 1 亿**，就先按“可以在 1 秒内跑完”判断；如果明显大于 $10^8$，就要考虑优化。时限是 2 秒时，可以按约 $2\times 10^8$ 次简单操作估算。

例如 $n$ 最大为 1000，$\mathcal{O}(n^{2})$ 代入后是 $10^6$，可以直接尝试；$n$ 最大为 100000，$\mathcal{O}(n^{2})$ 变成 $10^{10}$，就应该换方案，而 $\mathcal{O}(n \log n)$ 约为 170 万，计算量小得多。

> **先读范围，再估计算法能否通过。**
>
> 不要只代入样例中的几个数。样例能跑完，不代表最大数据也能跑完；我们选算法时要看题目允许的最大规模。

### 常数：同样是 $\mathcal{O}(n)$，每轮做的事也有多少之分

前面把 $n$ 次和 $10n$ 次都记成 $\mathcal{O}(n)$，是因为它们的增长方式相同。这里被省略的倍数，就体现了复杂度中的**常数**。

循环里只做一次整数相加，与每次都复制长字符串、频繁输入输出，花费的时间不同。简单循环即使略超过 $10^8$ 次，也可能在 1 秒内跑完；每轮操作较重时，就要给它留出更多时间。**$10^8$ 是选算法时的常用估算线，具体计算还要看每轮在做什么。**

### 看循环真正执行了多少次

不要只数代码里有几层循环。例如外层执行 $n$ 次，内层固定执行 10 次，总共约 $10n$ 次，仍是 $\mathcal{O}(n)$。

反过来，只有一层循环也可能很慢：如果每轮还调用一个会遍历 $n$ 个数的函数，总计算量仍可能是 $\mathcal{O}(n^{2})$。

**把每部分的执行次数乘起来，再把先后执行的部分加起来。** 判断复杂度时，真正重要的是操作次数如何随规模变化。

## 输入达到百万级：给 cin 关闭流同步

程序的时间还包括读入数据。**输入量达到 $10^6$ 时，即使算法只扫描一遍，也要防止 `cin` 输入较慢导致超时。** 在 `main` 的最开头、任何输入输出之前，加上两行：

```text
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

- 第一行关闭 C++ 输入输出流与 C 标准输入输出的同步，让 `cin`、`cout` 使用独立的缓冲方式。
- 第二行解除 `cin` 与 `cout` 的绑定，避免每次读入前都自动刷新 `cout` 的输出缓冲。

原来的 `cin >> n;` 写法不变。之后遇到大量输入，我们就沿用这个开头；输出换行用 `'\n'`，不用每次都会刷新缓冲的 endl。

> **关闭同步后，保持输入、输出各自使用同一套方式。**
>
> 输入使用 `cin`，就不要再交替使用 scanf 或 getchar。输出使用 `cout`，就不要再与 `printf` 交替输出，以免缓冲顺序混乱。
>
> 需要 `printf` 格式化输出时，可以输入全用 `cin`、输出全用 `printf`；不要在同一方向交替使用两套方式。后面仍然用 `printf` 处理小数位数、字段宽度等格式。

## 空间复杂度：需要保存多少数据

**空间复杂度**描述额外存储量怎样随规模增长。

- 只用几个变量保存余额、计数、最大值，额外空间是 $\mathcal{O}(1)$。
- 用数组保存 $n$ 个整数，空间是 $\mathcal{O}(n)$。
- 保存 $n$ 行 $m$ 列的矩阵，空间是 $\mathcal{O}(nm)$。

在我们的环境中，一个 `int` 通常占 4 字节。存一百万个 `int`，大约需要 4 MB；开二维数组时，要先把行数与列数相乘。

遇到较大的固定数组，可以把定义放在 main 外面，例如 `int a[1000005];`。这样使用全局存储，避免把大数组放在函数的栈空间里。数组仍然需要按题目最大规模开够，并检查下标。

## 例题精讲：P1567 · 统计天数

**原题：** [P1567 · 统计天数](https://www.luogu.com.cn/problem/P1567)。

**题意简述：** 输入连续 $n$ 天的最高气温，求气温严格上升的最长连续天数。$n$ 不超过 $10^6$，温度为 0 到 $10^9$ 的整数。

“连续上升”要求后一天比前一天高。温度相等时，这一段也会中断；只有一天，本身就算连续的 1 天。

### 先用手算找到需要记录的状态

以这组数据为例：

```text
6
20 21 22 19 20 21
```

前 3 天持续上升，第 4 天降温，之后又连续上升了 3 天。答案是 3。

我们需要两个长度：

- $\mathrm{length}$：**到今天为止，当前这一段连续上升有几天**。
- $\mathrm{best}$：**从开始到今天，见过的最长长度**。

还要用 $\mathrm{previous}$ 保存昨天的温度，才能与今天比较。

| 第几天 | 今天温度 | 与昨天比较 | 当前 $\mathrm{length}$ | 最长 $\mathrm{best}$ |
| --- | --- | --- | --- | --- |
| 1 | 20 | 第一日 | 1 | 1 |
| 2 | 21 | 上升 | 2 | 2 |
| 3 | 22 | 上升 | 3 | 3 |
| 4 | 19 | 没有上升 | 1 | 3 |
| 5 | 20 | 上升 | 2 | 3 |
| 6 | 21 | 上升 | 3 | 3 |

第 4 天中断后，$\mathrm{length}$ 从 1 开始，因为第 4 天本身是新的一段。$\mathrm{best}$ 保留已经出现过的 3，不随中断清零。

### 把更新规则翻译成代码

先读第一天的温度，令 $\mathrm{length}$、$\mathrm{best}$ 都为 1。之后每读一天：

1. 今天比昨天热，$\mathrm{length}$ 加 1；否则 $\mathrm{length}$ 重新设为 1。
2. 用当前 $\mathrm{length}$ 更新 $\mathrm{best}$。
3. 把今天的温度存进 $\mathrm{previous}$，给下一天使用。

### 逐条找到思路在代码里的位置

| 手算时做的事 | 程序怎样实现 | 为什么这样写 |
| --- | --- | --- |
| 第一天本身是一段连续的 1 天 | `length = 1`，`best = 1` | 这是后续比较的起点 |
| 按天依次处理剩下的气温 | $\mathrm{day}$ 从 2 循环到 $n$ | 第一天已单独读入 |
| 判断今天能否接在昨天后面 | $\mathrm{current}>\mathrm{previous}$ | 题目要求严格上升，相等也中断 |
| 能接上就延长，否则从今天重新开始 | `length++` 或 `length = 1` | 只改变当前这一段的长度 |
| 记住已经出现过的最长一段 | 若 $\mathrm{length}>\mathrm{best}$，就更新 $\mathrm{best}$ | 一段结束后，历史最好结果仍要保留 |
| 为明天准备“昨天的温度” | `previous = current` | 必须放在比较之后 |

读下面的程序时，试着指出每一段分别在实现表里的哪一步。写错时也按这个对应关系检查：是手算规则想错了，还是代码没有按规则执行？

```cpp
#include<bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, previous;
    cin >> n >> previous;
    int length = 1, best = 1;

    for (int day = 2; day <= n; day++) {
        int current;
        cin >> current;
        if (current > previous) {
            length++;
        } else {
            length = 1;
        }
        if (length > best) {
            best = length;
        }
        previous = current;
    }

    cout << best << '\n';
    return 0;
}
```

输入上面的 6 天数据，输出 `3`。再试 `5 5 5`，最长长度应是 1；试 `1 2 3 4`，应是 4。这两组温度分别对应 $n=3$、$n=4$，测试时记得先输入天数。

> **模拟时，状态更新的顺序要与规则一致。**
>
> 先比较 $\mathrm{current}$ 与 $\mathrm{previous}$，再把 $\mathrm{current}$ 保存到 $\mathrm{previous}$。如果一读入就覆盖 $\mathrm{previous}$，就相当于拿今天和今天比较。
>
> 同时分清“当前这一段”与“历史最好结果”：中断时只重置 $\mathrm{length}$，$\mathrm{best}$ 要保留。

### 再看这份程序的复杂度

每个温度只读取和处理一次，每天做固定次数的比较与赋值，所以时间复杂度为 **$\mathcal{O}(n)$**。最大 $n=10^6$，代入后是一百万这个量级，小于 $10^8$；同时程序已经给 `cin` 关闭流同步，处理百万个温度时也照顾到了输入速度。

计算时只需要昨天和今天的温度，以及两个长度，不需要保存全部温度，所以额外空间为 **$\mathcal{O}(1)$**。这个例子也说明：先想清楚下一步需要什么信息，再决定保存什么数据。
